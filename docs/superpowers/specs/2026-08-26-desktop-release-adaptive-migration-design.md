# Scientific Research OS 正式发布：适应性数据迁移设计

**目标：** 在不改变、不停机且不写入既有网页版系统的前提下，将其科研资料转换为桌面端可编辑、可检索、可备份的本地研究资料包，并为后续功能补齐建立稳定数据底座。

## 不可违反的兼容性约束

1. 网页端生产数据库、MinIO 对象、Redis、Neo4j、FastAPI 与前端静态站点均为只读来源；迁移程序不得执行 `INSERT`、`UPDATE`、`DELETE`、`ALTER`、`DROP` 或重新部署网页服务。
2. 所有桌面端工作必须在独立 Git worktree 和发布分支完成。除文档外，不得修改根目录的 `app/`、`web/`、`alembic/`、`docker-compose*.yml`、Nginx 配置或线上数据目录。
3. 正式迁移前，操作者必须生成 PostgreSQL 只读快照和 MinIO 对象清单；源库的表计数、最大更新时间及对象清单校验和将写入迁移报告。
4. 密码哈希、访问令牌、刷新令牌、企业微信密钥、支付凭据、Webhook 密钥和声纹向量不迁移。桌面端账户在首次启动时独立设置密码。
5. 桌面端导入仅写入临时工作区和新 SQLite 数据库。导入成功并经校验后才切换为当前资料库；失败时只删除临时目标，不接触网页端来源。

## 目标形态

迁移不是复制 PostgreSQL 表，而是生成一个可携带的 `.mbrp`（MicroBubble Research Package）文件。它是带版本、来源、校验和与映射报告的 ZIP 容器。桌面端导入器将其中的内容写入 SQLite 索引和本地研究文件工作区。

```text
网页端只读快照 ──> 导出器 ──> 语义转换器 ──> .mbrp
                                               ├── manifest.json
                                               ├── projects/
                                               ├── experiments/
                                               ├── meetings/
                                               ├── knowledge/
                                               ├── drive/
                                               ├── conversations/
                                               └── audit/
                                                            │
                                                            ▼
                                             桌面端预检、导入与本地索引
```

## 数据转换规则

| 网页端资料 | `.mbrp` 内容 | 桌面端使用方式 |
|---|---|---|
| 成员与资料 | `members.json`、项目联系人 | 建立本地账户/联系人；首次本地设密 |
| 项目、里程碑、任务 | `projects/<id>/overview.md`、`work-items.json`、`timeline.json` | 项目工作区中的可编辑计划与工作项 |
| 实验、数据、图表 | `experiments/<id>/` 下的 CSV、JSON、Markdown、图表元数据 | 导入 experiments、samples、measurements、ELN 与分析索引 |
| 会议、纪要、转录、录音 | `meetings/<id>/record.md`、`transcript.md`、附件 | 可编辑会议记录与可播放原始附件 |
| 知识库、论文、公式、图片 | `knowledge/<id>/document.*`、`metadata.json`、引用索引 | 本地知识文档、全文检索与引用 |
| 网盘、文件夹、版本、评论 | `drive/<id>/current/`、`versions/`、`comments.json` | 当前文件可编辑，历史版本只读可追溯 |
| 聊天历史与附件 | `conversations/<id>.md`、`<id>.json`、附件引用 | 可检索的历史对话，新对话由桌面端另行生成 |
| 通知、审计、AI Trace | `audit/*.ndjson` | 只读历史证据，不恢复为可执行任务 |

## 发布分层

1. **资料连续性发布：** 先让全部既有资料安全导入桌面端并可读取、搜索、编辑其可编辑载体。
2. **桌面功能补齐：** 以本地文件与 SQLite 索引为唯一数据源，逐批实现任务、会议、网盘、聊天和通知的桌面操作体验。
3. **正式版放行：** 仅在迁移演练、离线运行、备份恢复、安装升级、签名与回滚演练全部通过后发布。

网页端在整个过程持续作为原系统运行；迁移完成也不会删除、禁用或改写网页端数据。

## 验收门禁

- 导出前后来源表计数、对象数量和清单 SHA-256 一致；任一不一致即停止。
- `.mbrp` 的 `manifest.json` 声明格式版本、来源快照时间、实体计数、附件计数、警告和每个文件 SHA-256。
- 在一台无旧桌面数据的 Windows 测试机完成“安装 → 导入 → 搜索 → 编辑 → 备份 → 恢复 → 卸载 → 重装 → 恢复”闭环。
- 用只读账号复查网页端项目、任务、会议、知识库和网盘数据仍完全可用。
- 所有发布构建可由一个固定 Git 提交、锁定依赖、构建编号、签名记录和发布清单复现。

## 已知发布前缺口

- 桌面端尚无网页数据到 `.mbrp` 的导出、转换、预检或导入链路。
- 桌面端尚未提供任务、会议、成员、网盘和聊天历史的本地等价工作区。
- 备份恢复目前未定位真实 SQLite 文件；配置写入 SQL 有拼写错误，必须先修复并以真实数据库测试。
- 更新服务为占位实现，Windows 产物未签名；真实设备协议驱动尚未接入。

这些缺口必须通过桌面端新增模块解决，不能以修改或停用网页端作为代价。

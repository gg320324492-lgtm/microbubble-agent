# W101 P2 Auto-RAG Runbook (2026-08-01)

派工 v10 — W101 P2 主动 RAG Auto-RAG（任务触发自动检索背景知识）

## 1. 目标

任务/会议/知识创建时主动触发后台背景知识检索, 缓存 24h, 供后续 chat 复用.

## 2. 架构

```
[TaskService.create_task] --+
                             |
[MeetingService.create_meeting] --+--> [AutoRAGService.trigger_and_dispatch]
                             |              |
[KnowledgeService.create_knowledge] --+     v
                                   [retrieve_and_cache_task (Celery)]
                                          |
                                          v
                            [HybridRetriever.retrieve] -> [Redis 24h TTL]
```

## 3. 4 事件类型与优先级

| 事件类型 | 触发条件 | 优先级 | Cache TTL |
|---------|---------|--------|-----------|
| `task.create` | title+description ≥ 3 字符 | 6 | 24h |
| `task.update` | changed_fields 含 status/description/title/priority | 4 | 24h |
| `meeting.create` | title+description ≥ 3 字符 | 8 | 24h |
| `knowledge.upload` | title+content[:500]+tags ≥ 3 字符 | 10 | 24h |

## 4. 缓存 Key 规范

```
auto_rag:{event_type}:{entity_id}
```

例:
- `auto_rag:task.create:42`
- `auto_rag:meeting.create:7`
- `auto_rag:knowledge.upload:123`

## 5. Redis 缓存内容

```json
{
  "event_type": "task.create",
  "entity_id": 42,
  "query_hint": "完成微纳米气泡稳定性测试",
  "priority": 6,
  "hits": 5,
  "chunks": [
    {"id": 1, "title": "...", "content": "...", "score": 0.85},
    ...
  ]
}
```

## 6. 集成调用模式 (fire-and-forget)

```python
# task_service.create_task / meeting_service.create_meeting / knowledge_service.create_knowledge
# 末尾追加 (W101 +5 commit)
try:
    from app.services.auto_rag_service import auto_rag_service
    await auto_rag_service.trigger_and_dispatch(
        "task.create",  # or meeting.create / knowledge.upload
        task.id,        # or meeting.id / knowledge.id
        (title or "") + " " + (description or "")
    )
except Exception as _e:
    logger.debug(f"[W101 P2] auto-rag trigger failed (non-blocking): {_e}")
```

## 7. 公开 API

```python
from app.services.auto_rag_service import auto_rag_service, AutoRAGService

# 1. 触发信号检测 (sync)
decision = auto_rag_service.should_auto_retrieve(event_type, payload)
# 返回: {"should_retrieve": bool, "query_hint": str, "priority": int}

# 2. 触发并 dispatch (async, fire-and-forget)
result = await auto_rag_service.trigger_and_dispatch(
    "task.create", entity_id, query_hint
)
# 返回: bool (True if dispatched)

# 3. 读缓存 (async, 后续 chat_engine 集成用)
from app.services.auto_rag_tasks import get_cached_auto_rag
cached = await get_cached_auto_rag("task.create", 42)
# 返回: dict or None
```

## 10. 已知约束

- **不监听 task.update 实际变更**: 当前 task_service 无 update_task general 方法 (仅 update_task_status), task.update 事件类型已实现触发检测但无调用方, 留待 W101 P3 加 update_task general 方法后启用

- **不触发低频事件**: 当前仅触发 task/meeting/knowledge 创建 3 类高频事件, 不覆盖 update/delete

## 1. 故障现象

生产服务器 `https://agent.mnb-lab.cn/` 用户报告前端加载异常。诊断结果：

```
curl -sI https://agent.mnb-lab.cn/assets/index-5deb71a7.js
→ HTTP/1.1 404 Not Found
→ Content-Type: text/html; charset=utf-8
```

`/assets/index-5deb71a7.js` 在 nginx 上返回 **404**，但 `/assets/index-a1ffff69.css` 返回 **200**。SPA fallback 触发，nginx 把 HTML 当 JS 返回给浏览器 → 浏览器解析失败 → 前端白屏。

## 2. 根因（深挖）

### 2.1 main HEAD `cd2571db5` 的 dist 内容

```
git ls-tree -r main web/dist/ | grep "index-.*\.js$"
→ (空)
```

**main HEAD 的 web/dist/assets/ 里没有任何 `index-*.js` 主包文件**。只有 CSS + 各种 chunked `*-<hash>.js`。`web/dist/index.html` 引用 `index-5deb71a7.js`，但该 blob 不存在于 git tree 中。

### 2.2 追溯到 commit `a7ef24af7`（FIX-IMAGES-FRONTEND W99 +20）

```
git show --stat a7ef24af7 | grep web/dist | wc -l
→ 109 files changed  (174 deletions, 1 addition)
```

`a7ef24af7` commit 信息写："npm run build 成功（vite-plugin-pwa disable 模式）"。但实际：
- **174 deletions** — 删除了所有老 chunked 文件（`AgentTracesView-137302d1.js` 等）
- **1 addition** — 只在 `index.html` 加了 `<script src="/assets/index-5deb71a7.js">` 一行
- **`index-5deb71a7.js` blob 从未在 git tree 中出现过** — 在该 commit 之前/之后/之中都没有

**真相**: 该 commit 在前端跑了 `npm run build`，但 post-build 的 force-add 步骤**漏掉了新生成的 `index-*.js` 文件**，只 force-add 了 `index.html`（index.html 在 .gitignore 外但其他 dist 文件在）。结果 commit 删了所有老 chunked 文件 + 新加的 index.js 又没入 commit → 服务器端 `index.html` 引用一个**git 里不存在的 JS 文件**。

### 2.3 触发链

1. `a7ef24af7` (2026-08-02 02:48): build 但 force-add 漏 index.js → dist 损坏
2. server webhook `git pull + reset --hard origin/main` 拉取 main HEAD → 拉到损坏 dist → 404
3. `cd2571db5` 后续 W100 系列 commits 都改了 `app/` 没改 `web/`，没触发新 build → 故障持续

## 3. 修复方案

### 3.1 选项 A（推荐，已采用）：本地 `npm run build` 重建 dist + force-add commit

1. 在 main 仓库 `/e/microbubble-agent/web/` 跑 `npm run build`（node_modules 已存在）
2. 复制新 dist 到 worktree `/e/agent-fix-deploy/web/dist/`
3. `git add -f web/dist/` 强制 add（.gitignore 排除 dist）
4. commit + push origin
5. server webhook 自动拉取 → 服务器拿到新 `index-50879b4e.js` (131 KB main bundle)

### 3.2 选项 B（备选，未用）：改 deploy-auto.sh

不适用本案 — 问题不在 deploy 脚本（脚本是 git fetch + reset --hard，正确），而在于 main HEAD 本身就有损坏 dist。

### 3.3 为什么选 A 不选 B

- deploy 脚本逻辑正确（line 72-73 `git fetch origin main && git reset --hard origin/main`）
- 改 deploy 脚本无法修复 main HEAD 已损坏的 dist
- 真修复必须重建 dist + 推 origin 让 webhook 拉

## 7. 永久铁律沉淀

### 7.1 build 后 force-add 必须覆盖所有 dist 子文件

`git add -f web/dist/` 必须包含**所有**子目录 + assets，否则 commit 会出现"index.html 引用不存在文件"。

### 7.2 W68 H-3 PWA 禁用决定延续

PWA 仍然 disabled（vite-plugin-pwa `disable: true`）。sw.js + manifest 不生成是**预期**行为，不是 bug。

### 7.3 主包 `index-*.js` 必须在 .gitignore 排除清单 + force-add 双策略保护下入仓

CLAUDE.md 永久铁律：
- `web/dist/` 在 `.gitignore` 中
- 任何 build commit 必须 `git add -f web/dist/` 而非 `git add web/dist/`
- force-add 后必须 `git status` 检查 0 unstaged / 全部入仓
- commit message 必须含 `build: dist for <hash>` 标识让审计可追

### 7.4 dist 完整性自检脚本（建议未来 PR 加固）

```bash
# 部署前自动跑（脚本可挂 deploy-auto.sh line 100 之后）
INDEX_JS=$(grep -oE 'assets/index-[A-Za-z0-9_-]+\.js' "$PROJECT_DIR/web/dist/index.html" | head -1)
INDEX_HASH=$(basename "$INDEX_JS")
if [ ! -f "$PROJECT_DIR/web/dist/$INDEX_JS" ]; then
    log "FATAL: dist/index.html 引用 $INDEX_JS 但文件不存在 — main HEAD 损坏"
    log "FATAL: 需要本地跑 npm run build + force-add commit 修复"
    exit 1
fi
```

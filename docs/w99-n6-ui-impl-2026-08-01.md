**新逻辑** (W99 N-6):
```python
if payload.message_id is not None and payload.session_id:  # 改用 session_id 守卫
    # 1. 优先按 session_id 定位最近 search_log
    target_q = select(SearchLog).where(SearchLog.session_id == payload.session_id)...
    target = await db.execute(target_q).scalar_one_or_none()
    # 2. 登录用户兜底: session 找不到时按 user_id 兜底
    if target is None and user_id > 0:
        target_q_alt = select(SearchLog).where(SearchLog.user_id == user_id)...
        target = await db.execute(target_q_alt).scalar_one_or_none()
```

**派工 v10 §2.5 描述对齐**: "放开 user_id > 0 守卫, 匿名用户存 session_id + IP hash" — 落实 session_id 桥接 (IP hash 留 P2, 优先消除盲区不引入额外 PII).

### §1.6 改进 (6) — analytics answer_rating 聚合 (`app/api/v1/analytics.py`)

**新增 2 个聚合块** (不破坏老 schema, 仅 SQL 新查询):

```python
# 块 1: by_rating 桶 + 衍生指标
by_rating = {
    "up": 25,           # 👍 count
    "down": 5,          # 👎 count
    "unrated": 70,      # 无反馈 count
    "total": 100,       # 总数
    "answer_rate": 30.0,    # (up + down) / total * 100
    "upvote_rate": 25.0,    # up / total * 100
}

# 块 2: 14 天每日趋势
answer_trend = [
    {"date": "2026-08-01", "up": 5, "down": 1, "unrated": 14, "total": 20, "answer_rate": 30.0},
    ...
]
```

**SQL 关键点**:
- `COALESCE(answer_rating, 0)` 把 NULL 归入 unrated 桶
- `FILTER (WHERE ...)` 一次查询出多桶
- 空数据兜底: total=0 → rate 全 0 (不抛 500)

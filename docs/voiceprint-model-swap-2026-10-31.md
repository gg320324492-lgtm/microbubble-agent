# Phase 1 报告：声纹嵌入模型换代对比（ERes2Net vs ERes2NetV2）（2026-10-31）

> **一句话结论：Phase 1 不通过。**
> **ERes2NetV2 在我们自己的数据上全面略差于现役 ERes2Net**：argmin 正确率 −0.1 ~ −1.0 点、
> 同场验证 EER **+1.7 ~ +2.4 个百分点**（更差）、跨场验证 EER 4 差 1 平、认回段数少 250–440、
> 双指标净增益 −121 ~ −402。**换上去是退步，不予采纳。**
>
> ⇒ 叠加 Phase 0 的结论（「长 enrollment 质心在现役模型下无增益」），
> **模型的代际与 enrollment 的长度这两条杠杆都已被实测否掉。**
> ⇒ 剩下唯一没被否掉的杠杆是 **Phase 1b（diarization 聚类 → 簇质心命名）** —— 本轮拿到了它的**新支持证据**：
> **跨场 EER 20.7% vs 同场 EER 11.6% ⇒ 近一半的错误来自「声学环境变化」，
> 而「用长段/簇级对象去命名」正是对症的药。**
>
> ⚠️ 同时回答了上游最关心的那个问题：**ERes2NetV2 的长度敏感性并没有比现役模型更低**
> （10s 真实语音 +60s 静音 ⇒ 余弦 0.696 vs 0.658，**同一量级**）
> ⇒ Phase 0 的「整段质心」在**两个模型里都**只在「簇质心↔簇质心」范式成立。

## 1. ⭐ 方法论：两个模型的空间不能横比距离

ERes2Net 与 ERes2NetV2 的嵌入空间**互不相通**（同一段音频两模型余弦 **−0.0113**）
⇒ **余弦距离的绝对值不可跨模型比较**（「0.35 比 0.40 好」在两个空间里没有意义）。

⇒ 本报告只用**空间无关**的指标下跨模型结论：

| 指标 | 为什么空间无关 | 判读 |
|---|---|---|
| **argmin 正确率** | 只问「真主人的质心是不是最近的那个」⇒ 比的是**排序**不是距离 | 主指标 |
| **双指标**（认回 / 真抢走 / 净增益） | 都是**计数** | 主指标 |
| **验证 EER** | 正负样本的**分布形状**比较，不看绝对刻度 | 主指标 |
| 同空间内的距离分布 | ❌ 不可横比 | **只作参考** |

⚠️ **候选池必须与被测嵌入同空间** —— 这是本脚本第一版的 bug：拿 ERes2Net 的向量去和 V2 的向量比 = 纯噪声。
⇒ 候选池做成**可插拔**：

| 池 | 空间 | 用途 |
|---|---|---|
| `pool_db` | 仅 ERes2Net | **生产现状参照**（库内现役质心，部分 in-sample ⇒ 偏乐观） |
| `pool_rebuilt` | 两个空间各自重建 | ⭐ **跨模型比较只用这个**（构造相同，只差模型） |

「重建池」= 该成员**全部台账段**的均值（与库内生产质心同构，但在本空间里算）。

### 1.1 回归核对：Phase 1 的 ERes2Net 臂**精确复现** Phase 0

用 `pool_db` 跑 ERes2Net 臂 ⇒ 与 Phase 0 的数字**逐项相同**（16/16 全过）：

| 变体 | argmin | 认回 | 真抢走 | 净增益 |
|---|---|---|---|---|
| seg_old | 0.8842 = 0.8842 ✅ | 3736 = 3736 ✅ | 777 = 777 ✅ | 2959 = 2959 ✅ |
| c10 | 0.8751 ✅ | 3617 ✅ | 601 ✅ | 3016 ✅ |
| whole | 0.7718 ✅ | 4035 ✅ | 591 ✅ | 3444 ✅ |
| c10_longest | 0.8196 ✅ | 2413 ✅ | 561 ✅ | 1852 ✅ |

⇒ **Phase 1 的评测管线与 Phase 0 可比**（类 20.220：先证明测量本身可信）。
并且 **Phase 0 的 `whole` 净增益 +485 在本轮同样成立** ⇒ 两轮结论互相印证。

### 1.2 输入同一性（跨模型比较的前提）

Phase 1 不是重新推导素材，而是**读 Phase 0 的 `meta.json` / `runs.json` 作为素材定义**，
重建音频切片后**逐条比对**（meeting / seg_idx / start / end / kind / run / chunk）：
**14145 / 14145 一致 ✅**（`data/vp_phase1/identity_check.json`）。
⇒ 两个模型吃的是**逐条对齐的同一批 numpy 数组**（同一进程、同一批切片）⇒
「模型差异」与「输入差异」严格可分（类 20.249 ⑧）。

### 1.3 ⛔ 一个被自己否掉的指标：EER 的样本集必须锁死

第一版 EER：负样本取「别人的**所有**段」⇒ ①**跨会议**（声学条件不匹配）②每个段被重复计入 47 次。
改好后又发现第二个问题：**各变体可用的 (会议, 成员) 组合数不同**
（`seg_old` 45 / `c5`·`c10`·`c10_longest` 41 / `whole` 39）⇒ EER 的样本集不同
⇒ `whole` 的 EER 0.2077 是在**更容易的子集**上算的（少了 300 段难样本）。
⇒ **锁死共同样本（39 个 (会议,成员) 组合）后，`whole` 的 EER 优势消失**。

⚠️ **这是一个靠不住判据就会得出错误结论的实例**：如果不锁样本，
会得出「长段质心把 EER 从 0.2067 降到 0.2077…等等其实更好」的错觉。
⇒ 记一笔：**凡「各组样本集不同」的指标，横比前必须先取共同样本**（类 20.249 ⑧ 的又一次）。

## 2. 探针结果（两模型并排）

> 真实语音基线（会议 255 的真实转录段）⇒ **订正了 Phase 0 用随机噪声测的偏悲观数字**。

| 项 | ERes2Net（现役） | ERes2NetV2 | 说明 |
|---|---|---|---|
| 实现 | `ERes2Net_aug` | `ERes2NetV2` | 官方 modelscope 实现 |
| 参数 | 55.2 M | **17.9 M** | V2 是剪枝版（小 3 倍） |
| 逐条吞吐（20 条真实 2–4s，独占 GPU） | **0.0126 s/段** | **0.0627 s/段** | V2 慢 5× |
| 逐条吞吐（GPU 有竞争时） | 0.0356 s/段 | 0.1456 s/段 | 竞争下都退化 |
| 整段嵌入 10 s | 0.06 s | 0.08 s | |
| 整段嵌入 60 s | 0.31 s | 0.31 s | |
| 整段嵌入 300 s | 0.89 s | 2.83 s | |
| 整段嵌入 **600 s** | **134.98 s** ⛔ | **7.29 s** ✅ | **V2 没有长音频的算力爆炸** |
| 长度敏感性：10s 真实语音 +5s 静音 | 0.9439 | 0.9461 | |
| 长度敏感性：+20s 静音 | 0.8331 | 0.8255 | |
| 长度敏感性：**+60s 静音** | **0.6581** | **0.6959** | ⇒ **V2 并不更不敏感** |
| 朴素批量（fbank pad 到同长、无 mask）vs 逐条：max abs diff | **158.54** ⛔ | 0.0996 | |
| 朴素批量：平均余弦 | 0.9742 | 0.9579 | ⇒ **批量不是免费的** |

### 2.1 三个探针结论

1. ⭐ **「ERes2NetV2 的长度敏感性更低 ⇒ 整段质心可直接用于逐段匹配」这个假设被否掉。**
   V2 在 +60s 静音下余弦 0.6959 vs 现役 0.6581 —— **同一量级，V2 甚至略"更敏感"与否都不显著**。
   ⇒ **Phase 0 的「整段质心属于另一个表征空间」这条结论对两个模型都成立** ⇒
   **整段/簇质心只在「簇质心↔簇质心」范式（Phase 1b）里有价值。**
2. ✅ **V2 有一个真实的工程优势**：600 s 整段嵌入 **7.29 s** vs 现役 **134.98 s**（18×）。
   ⇒ 现役模型在 >300 s 的整段嵌入上**工程不可用**（Phase 0 因此漏掉了韩重阳 600 s /
   陈天祥 398 s / 蒋芦笛 318 s 三条最长段）；V2 没有这个问题。
   ⇒ **若将来走 Phase 1b（需要长段/簇级对象），V2 在这一点上是有用的** ——
   但这**不能**用它来抵「逐段判别力略差」这件事。
3. ⛔ **朴素批量会静默改掉嵌入**：现役模型 max abs diff **158.54**（灾难级），
   V2 0.0996（平均余弦 0.958 ⇒ 约 4% 的余弦损失）。
   ⇒ 本项目**不做真批量**（逐条已够快：1.1 万段 V2 约 20 分钟）⇒ 零 padding 风险。
   ⇒ V2 的 `TSTP` 池化**没有 mask**（`x.mean(dim=-1)` 直接吃补零帧）；
   要真批量就得在本仓实现 mask 化 TSTP，而 `speakerlab`（官方实现）**不在 pip 包里**
   ⇒ 那是一笔有风险的改造，**收益不足以支撑**。

## 3. 主结果：ERes2Net vs ERes2NetV2

共同分母 **7731 段**（双指标）/ **2866 段**（argmin）/ **39 个 (会议,成员) 组合**（EER）；
候选池 = `pool_rebuilt`（13 人，两个空间各自重建）。

### 3.1 无阈值判别力（argmin 正确率）

| 变体 | ERes2Net | ERes2NetV2 | 差 |
|---|---|---|---|
| `seg_old`（短段均值 = 现役口径） | **88.4%** | 87.4% | **−1.0 点** |
| `c5`（5s 窗均值） | 87.3% | 86.9% | −0.4 点 |
| `c10`（10s 窗均值） | 87.5% | 86.8% | −0.7 点 |
| `c10_longest`（只用最长一段） | 82.0% | 81.2% | −0.8 点 |
| `whole`（整段嵌入） | 77.2% | 77.1% | −0.1 点 |

⇒ **5 个变体、5 个全降。**

### 3.2 验证 EER（minimax 形式，跨场留出）

| 变体 | 跨场 EER（难） | 同场 EER（最易，诊断用） |
|---|---|---|
| | 现役 → V2 | 现役 → V2 |
| `seg_old` | 0.2067 → **0.2164** ❌ | 0.1162 → **0.1329** ❌ |
| `c5` | 0.2138 → **0.2090** ✅ | 0.1295 → **0.1537** ❌ |
| `c10` | 0.2118 → **0.2114** ≈ | 0.1312 → **0.1549** ❌ |
| `c10_longest` | 0.2114 → **0.2116** ≈ | 0.1751 → **0.1920** ❌ |
| `whole` | 0.2077 → **0.2110** ❌ | 0.1262 → **0.1505** ❌ |

⇒ **跨场 EER：4 差 1 好 1 平（差异都在 ±0.01 量级，实质是持平）；
同场 EER：5 个全差，且差得更多（+1.7 ~ +2.4 个百分点）。**

⚠️ **同场 EER 是「实现有没有问题」的自检**：同场是最容易的任务（质心就用该场自己的段建的）。
若 V2 实现有致命错误，这里会**大幅**退化；实测只差 1.7–2.4 个点，且 V2 在跨场 `c5` 上还略好一点
⇒ **V2 不是「没生效」，是「在我们这批数据上确实弱一点」。**

### 3.3 类 20.226 双指标（认回 / 真抢走 / 净增益）

| 变体 | 认回（现役 → V2） | 真抢走（现役 → V2） | **净增益** |
|---|---|---|---|
| `seg_old` | 3285 → 2973 (−312) | 442 → 383 (−59) | 2843 → 2590 (**−253**) |
| `c5` | 3146 → 2850 (−296) | 338 → 287 (−51) | 2808 → 2563 (**−245**) |
| `c10` | 3180 → 2833 (−347) | 317 → 268 (−49) | 2863 → 2565 (**−298**) |
| `c10_longest` | 2276 → 2109 (−167) | 320 → 274 (−46) | 1956 → 1835 (**−121**) |
| `whole` | 3620 → 3180 (−440) | 303 → 265 (−38) | 3317 → 2915 (**−402**) |

⚠️ **读法**：V2 的「真抢走」也更低（少抢 38–59 段），但那是因为**它连认回都少**——
少抢是"认不出人"的副作用，不是好事。**净增益一律更低（−121 ~ −402）。**

### 3.4 现役生产质心的 in-sample 红利（一个附带量化）

| 池 | 认回 | 真抢走 | 净增益 |
|---|---|---|---|
| `pool_db`（库内现役质心） | **3736** | 777 | 2959 |
| `pool_rebuilt`（同口径重建） | 3285 | 442 | 2843 |

⇒ **库内现役质心的认回数里有 451 段（13.8%）是 in-sample 撑起来的**
（现役质心的一部分就是用这些台账块建的）⇒
**「现役系统认回 3736/7731」这个数**不能当作「现役系统的真实能力」，真实值更接近 **3285**。

**Phase 1 = 不通过（FAIL）。** ERes2NetV2 不予采纳。

判据（全部在共同分母 / 共同样本上）：

| 判据 | ERes2Net | ERes2NetV2 | 结果 |
|---|---|---|---|
| argmin 正确率 | 88.4% | 87.4% | ❌ V2 差 1.0 点（5 个变体全差） |

## 5. ⭐ 本轮拿到的、对路线最有价值的三个数字

### 5.1 「跨场 EER 20.7% vs 同场 EER 11.6%」⇒ 近一半的错误来自**声学环境变化**

同场 EER 11.6%（现役 `seg_old`）已经是"质心就用该场自己的段建的"这种**最有利**的情形
⇒ 即便如此，**同一场会议里**的短段 ↔ 成员质心判别也有 11.6% 错误。
跨场（质心来自别的会议）⇒ **20.7%**。
⇒ **误差预算的一半在「跨场鲁棒性」上** ⇒ 换模型、换 enrollment 长度都打不到这一半；
**对症的是「让命名对象本身带上环境信息」（簇质心 / diarization）**。

### 5.2 我们的场景难度比官方 benchmark 高一个数量级

官方 Vox1-O：ERes2Net EER **0.84%**、ERes2NetV2 **0.61%**；
我们（真实会议、远场、多说话人、口音、ASR 切段）：**跨场 20.7% / 同场 11.6%**。
⇒ **差 14–26 倍。** ⇒ **官方 benchmark 的排序不能代表我们场景下的排序** ——
ERes2NetV2 在 2 s 干净语音上 EER 减半（3.28%→1.48%），在我们这儿却略差。
⇒ **模型选型必须在我们自己的数据上量**（这正是 Phase 1 的价值：否掉了一个「看起来显然」的改动）。

### 5.3 「换范式」这条路现在有了**独立于模型**的支持

Phase 0 的 `whole` 结果（同人跨场距离 0.3975→0.3894，配对 −0.0144 显著）+ 本轮的
**同场 EER 里 `whole` 0.1262 vs `seg_old` 0.1162**（长段质心同场略差）
⇒ 合起来是一句话：**长段/簇质心对「声学环境变化」更鲁棒**（跨场更好），但对「同场内的近邻判别」更钝。
⇒ ⇒ **Phase 1b 的判据不能用 argmin，必须用 EER（验证任务）** ——
argmin 会因为 regime 偏移把长段质心判低（Phase 0 就是这么误判的）。

## 6. 对路线的影响

| 杠杆 | 状态 | 依据 |
|---|---|---|
| 换模型：**ERes2Net → ERes2NetV2** | 🔴 **实测否掉** | 本报告 §3/§4 |
| 换模型：CAM++ | ⚠️ **未测**（模型未缓存，本轮未下载） | 见 §8 |
| 重建 enrollment（长段质心） | 🔴 **实测否掉** | Phase 0 报告 |
| **Phase 1b（diarization → 簇质心命名）** | 🟢 **现在最该做**，且**判据要用 EER** | 本报告 §5.1/§5.3 |
| 录入入口改 ≥30s + 样本留档 | 🟡 仍值得，但理由是**可审计 + Phase 1b 的硬前置**，不是修当前匹配 | Phase 0 §7.3 |

**建议的重排**

1. **Phase 1b**（diarization 聚类 → 簇质心 ↔ 成员质心命名）。
   - 用现役 ERes2Net 即可（换模型已被否）。
   - ⭐ **判据**：跨场验证 EER（锁死共同样本），目标是把 20.7% 压下来；
     **不要**用 argmin（它对长段质心有 regime 偏置）。
   - ⚠️ 若簇质心要做 >300 s 的整段嵌入 ⇒ 现役模型 600 s 要 135 s（工程不可用）
     ⇒ 要么控制在 ≤300 s，要么用 V2（7.3 s）**只做簇质心的计算**（但 V2 的逐段判别力略差）——
     这个组合值得单独量一次。
2. **CAM++**（若要补齐模型对比）：社区数据里它的短段证据不如 ERes2NetV2，
   但**我们自己的数据已经证明社区排序不可外推** ⇒ 值得自己量一次。
3. **降噪前端**（ClearerVoice 等）：跨场 EER 20.7% ⇒ 近一半误差在环境变化上 ⇒
   **对症的是把环境变干净，而不是换一个更强的说话人嵌入模型。**
   ⇒ 这条路本轮**没有测**，但从 §5.1 的误差预算看，它可能比换模型更对症。

## 7. 限制

1. **只测了 2 个模型、1 个场景**（8 场会议 + 台账 2866 段真值）。CAM++ 未测。
2. **台账覆盖只有 2866 段真值**，且集中在 19 人（短插话型学生多）⇒
   样本量对「短插话型成员之间是否可分」的结论仍然不足（类 20.243 的老问题）。
3. **V2 的 fbank / 池化口径完全照搬现役** ⇒ 如果 V2 官方推荐不同的分帧
   （例如 10 s 而非整段），本报告没有覆盖那种用法。
4. **没有测降噪前端**、没有测 diarization 聚类本身 ⇒ §6 的第 1/3 条是**推论**，不是实测。
5. **argmin 的 5 个变体各自用**自己的**质心集** ⇒ 变体之间可比，但**变体内部**是自洽的；
   跨变体比较 argmin 时要注意「池组成不同」（如 `whole` 只有 37 个质心）。
6. **生产未改**（SQL 回读：voice_embedding / voice_sample_count / voice_confirmed_at 均 0 行差异）。

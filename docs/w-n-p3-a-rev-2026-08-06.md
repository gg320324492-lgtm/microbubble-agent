### 2.2 53+ 张表全栈投入估算

按 0.75 天/1 表 × 53+ 张表 ≈ 40 天 (~8 周), 但需考虑:
- **复合 Index**: Prisma 10.x `@@index([a, b], name: "...")` 不支持, 命名迁移需统一决策
- **Enum**: PostgreSQL enum (meetings.status, tasks.priority) Prisma 有限支持, 部分场景需 fallback raw SQL
- **关联测试**: 184 文件迁移期 = 6-12 个月过渡
- **部署链断裂**: alembic 链改写 + 服务器 webhook 重测 + 本地 docker cp 流程

**53+ 张表全栈投入**: 8-15 周 (派工 brief 估 11.5-15 周, 实测偏上限).

### 2.3 5 大实战发现 (派工 brief 路径无预警)

1. **Prisma regex 解析陷阱**: `{}` 含 `{"{}"}` 默认值需 non-greedy `.*?\n\}` 模式
2. **Prisma DateTime tz 行为**: 默认 `Timestamptz`, 字段精度需显式 `@db.Timestamptz(6)`
3. **Prisma 无原生 FK ondelete**: Prisma 10.x 仅支持 `references` 注解, 53+ 张表迁移涉及大量手写 validate
4. **Prisma 复合 Index 命名**: `@@index([a, b], name: "...")` Prisma 10.x 不支持
5. **Prisma Float vs Decimal 区别**: Prisma Float 默认 Double precision, 字段定义需 Decimal 时需 `@db.Decimal(p, s)`

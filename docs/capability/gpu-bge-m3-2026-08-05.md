## 4. 关键能力实测: `token_embeddings`

late chunking 的核心不是"哪个模型", 而是**模型能否暴露 per-token 向量**. `LateChunkingService`
(`app/services/late_chunking_service.py`) 只依赖两个接口:

```python
tokenizer = self._model.tokenizer          # → attention_mask
output = self._model.forward(inputs)       # → token_embeddings, shape (batch, tokens, dim)
```

用**已缓存的 Qwen3** 在 GPU 上实测 (零下载):

```python
m = SentenceTransformer('Qwen/Qwen3-Embedding-0.6B', device='cuda', trust_remote_code=True)
feats = m.tokenizer('微纳米气泡 ζ 电位与传质研究。'*20, return_tensors='pt',
                    truncation=True, max_length=8192)
out = m.forward({k: v.to('cuda') for k, v in feats.items()})
```

结果:

```
load_sec: 8.1
has_tokenizer: True
max_seq_length: 32768
dim: 1024
forward_keys: ['attention_mask', 'input_ids', 'sentence_embedding', 'token_embeddings']
token_embeddings_shape: (1, 281, 1024)
```

逐条对照 `LateChunkingService` 的要求:

| 要求 | 实测 | 判定 |
|------|------|------|
| `model.tokenizer` 可调用, 返回含 `attention_mask` | `forward_keys` 含 `attention_mask` | ✅ |
| `model.forward(inputs)` 返回含 `token_embeddings` | `forward_keys` 含 `token_embeddings` | ✅ |
| `token_embeddings` shape `(batch, tokens, dim)` | `(1, 281, 1024)` | ✅ |
| 长上下文 (late chunking 前提是"一次编码整篇") | `max_seq_length = 32768` (远超 service 默认 `max_length=8192`) | ✅ |
| 维度与 104 迁移的 `late_embedding` 列一致 | 1024d | ✅ |

→ **能力完备**. `LateChunkingService(model=SentenceTransformer(...))` 可直接替换 MockModel.

## 5. 为什么用 Qwen3 而非 bge-m3 (决策依据)

| 维度 | Qwen3-Embedding-0.6B | BAAI/bge-m3 |
|------|---------------------|-------------|
| 已缓存 | ✅ 1.2GB | ❌ 需下载 ~2.7GB (**brief 严禁**) |
| 维度 | 1024d | 1024d (**相同**) |
| `token_embeddings` 接口 | ✅ 实测通过 | 同为 ST 模型, 预期同样支持 (**未实测**) |
| 生产角色 | **默认** (`EMBEDDING_MODEL_NAME` 默认值) | 灰度候选 (`EMBEDDING_BACKEND=bge_m3` 才启用) |
| bench 结果可迁移性 | **直接反映当前生产** | 反映一个尚未启用的候选 |

Qwen3 不仅无需下载, 而且**是当前生产实际在跑的模型** — 用它跑 late chunking bench, 结论直接适用于生产, 比 bge-m3 更有决策价值.

bge-m3 的真 bench 不作废, 记入触发条件文档留 future PR (见 `docs/bench/late_chunking_real_bench_threshold.md`).

## 6. 现有 mock bench 的局限 (真 bench 的必要性)

`scripts/bench_late_chunking.py` 的 `MockModel`:

```python
def forward(self, inputs):
    n = inputs["attention_mask"].shape[1]
    return {"token_embeddings": np.ones((1, n, 1024), dtype=np.float32)}   # 全 1
```

全 1 向量 → 所有 token 向量恒等 → mean-pool 后所有 chunk 向量恒等 → `chunk_late_score` 恒为
`np.dot(ones(1024), ones(1024)) == 1024.0`, 与 `parent_score` 完全相同.

`results/late_chunking_bench_2026-08.json` (`"mock": true`) 因此**只验证了管线不崩, 未验证任何检索信号**:
无法回答 "late chunking 相比 parent-doc 单向量, 召回是否更好". 这正是真 bench 要补的。

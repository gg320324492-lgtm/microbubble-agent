## 一、变体与口径

候选质心全部**留出被评场**（strict），同一 harness / 同一样本 / 同一池规则（cohort = 台账素材 ≥2 场的 17 人）：

| 变体 | 质心 = | 语义 |
|---|---|---|
| **base** | 其它**每场**质心均值（= 现 strict LOO 基线） | 每场等权 |
| seg_mean | 其它场全部台账段均值 | 每段等权 |
| sqrt_weighted | 每场质心按 √段数 加权 | 折中 |
| prod（参照） | 库里现役质心 | ⚠️ 含被评场素材 ⇒ in-sample 上界 |

⚠️ 口径（类 20.252/20.254）：argmin 基线口径，**不与簇质心口径的 0.5604/0.6350 横比**；
n=2866（真值人无场外素材的段计入错误，与 Phase 1l 的 n=2829/0.5426 差 0.5 点在此）；
EER 同协议跨变体可比，**prod 的 EER 样本集不同（pos 2215 vs 2829）不可横比**。

## 二、主结果

| 变体 | strict 段级 | vs base 净增益（绝对数） |
|---|---|---|
| base（每场等权=现基线） | 0.5949 | — |
| seg_mean（每段等权） | 0.5984 | +139/−129 = **+10** |
| sqrt_weighted（√段数） | 0.6022 | +108/−87 = **+21** |
| prod（参照，in-sample） | 0.6445 | （缺口 4.2 点未被关闭） |

EER：base 0.2199 / seg_mean 0.2202 / **sqrt 0.2158** —— 基本持平（−0.4 点）。

## 三、⛔ 为什么不通过（三条）

1. **均值增益被波动淹没**：净 +21/2866（+0.7 点），而逐场波动达 15 点
   （m259: base 0.6338 → seg_mean **0.4789**）、逐人波动 −25…+30 —— 类 20.226 ⑧ 的
   「净增益 <5 不写库」按全域口径同样适用。
2. **场间素材极不均衡 ⇒ 任何按段加权被单场主导**：王天志 9 场共 953 段，其中
   250 场 423 + 256 场 243（70%）；陈天祥 262 一场 138/186；吴孟铨 262 一场 123/154。
   按段/√段加权后，质心漂向主导场的声学条件 ⇒ 在声学不同的被评场崩
   （m259 之于 250 主导的王天志质心）。**base 的每场等权已是最均衡的跨场采样**。
3. **选择性替换 prod 质心：本评测集无法诚实回答**。
   干净赢家（净≥+5 且损失≤2）= 韩重阳(+30/−2)、肖佐林(+16/−1)、王书馨(+6/−1)；
   把它们替换进 prod 池后 **net −129**（韩重阳 +1/−126）—— 但该对照对替换者
   结构性偏置：prod 质心**含**被评场素材、替换者质心**留出**被评场 ⇒ 输赢主要由
   in-sample 差决定，不是部署形态的差异。而替换者的 prod 素材来源恰好都在
   评测集内（262 报告块 / 250）⇒ **不存在无偏的评测场**（263 无这三人）。
   ⇒ 类 20.226 ④：基线无法判断改好改坏 ⇒ **不写库**。

## 四、⭐ 机制收获：缺口重定位

prod(0.6445) − 最优 strict(0.6022) ≈ 4.2 点，三种加权都关不掉 ⇒ 缺口**不在加权方式**，
在**素材源**：

| | prod 质心用的素材 | strict 能用的素材 |
|---|---|---|
| 形态 | 长连续干净段（151 的 332 段 / 262 的 202 段报告块） | 台账标记段（短、散、场间失衡） |
| 量级 | 小时级音频 | 共 2866 段且 70% 集中在个别人个别场 |

⇒ 与 Phase 0 的结论（决定 enrollment 质量的是**素材条数/声学多样性**）在「源」的层面闭合：
跨场**多条**采样已经在 base 里实现了，再加权只是洗牌；要继续缩小缺口，杠杆是
**从原始音频的长连续段做跨场 enrollment**（Phase 0 的 whole 方向 —— ⚠️ 它属另一表征空间，
只能按 Phase 1b 的「簇质心↔簇质心」模式用，进不了现役逐段流水线）。

## 五、遗留（供主指挥取舍，本轮均未做）

   （+30/+16，损失有界）；但替换 prod 质心的收益要在**他们素材来源场之外的新会议**
   上才能无偏测。等下一场含这两人的会议有台账后，一次 A/B 即可定。
2. **tiebreaker 已修待生效**：`get_adjudications`/`AdjudicationResolver` 加

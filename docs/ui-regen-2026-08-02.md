## 2. 验收用例

### 2.1 桌面端

| 用例 | 步骤 | 期望 |
|------|------|------|
| ① hover 显示 | 鼠标移到 assistant 完成态气泡 | 右下角渐显 🔄 + 📋 |
| ② regenerate 点击 | 点 🔄 | "正在重新生成..." toast + 新 SSE 流式开始 |
| ③ regenerate 重复点 | 流式生成中再点 | disabled 不触发 + toast "当前正在生成中，请先点 ⏹ 停止" |
| ④ copy 点击 | 点 📋 | clipboard 写入 + toast "已复制" + 按钮变 ✅ 1.5s |
| ⑤ copy 失败 | http 环境 (clipboard API 不可用) | execCommand fallback + toast "已复制" 或 错误提示 |
| ⑥ 键盘 a11y | Tab 到 ChatMessageActions + Enter | 按钮聚焦 + 触发 |

### 2.2 移动端

| 用例 | 步骤 | 期望 |

## 3. 调试技巧

### 3.1 regenerate 不工作

```bash
# 1. 检查 useChatStream.sendMessage 是否能直接调
grep -A 5 "async function sendMessage" web/src/composables/chat/useChatStream.ts | head -20

# 2. 检查 messages 是否含目标 msg
# 浏览器 console:
JSON.stringify(useChatStream().messages.value.map(m => ({id: m.id, role: m.role, content: m.content.slice(0, 20)})))

# 3. 检查 regenerate handler 是否被调用
# ChatMessageActions.vue 的 onRegenerateClick 加 console.log:
console.log('[regenerate] clicked', msg.id)
```

### 3.2 copy 失败降级

```bash
# 检测 clipboard API 可用性
# console:
!!navigator?.clipboard?.writeText  # true = 现代浏览器, false = http 或老 Safari

# 检测 execCommand fallback
document.queryCommandSupported('copy')  # true = 可降级
```

### 3.3 dark mode 文字看不清

```css
/* web/src/components/chat/ChatMessageActions.vue */
[data-theme='dark'] .action-btn {
  color: var(--color-text-secondary);  /* 检查 vs design token */
}
[data-theme='dark'] .action-btn:hover:not(:disabled) {
  background-color: rgba(255, 122, 92, 0.18);  /* 提高透明度到 0.18 */
  color: var(--color-primary, #ff7a5c);
}
```

## 4. 监控指标

- **regenerate 使用率**: `useChatStream.sendMessage` 调用次数 / 总 SSE 启动次数
- **copy 使用率**: clipboard.writeText 调用次数 / 总消息数
- **regenerate 失败率**: 找不到前置 user / 正在生成中 / 跨 session 拦截的比例
- **copy 失败率**: clipboard API + execCommand 失败的总次数

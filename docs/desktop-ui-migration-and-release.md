# 桌面端 UI 原生化重设计 + 国内发布通道方案

> 2026-09-08 v2 · ①桌面 UI 定位为**真桌面原生软件**（否决 v1 的"壳 + Bridge"套壳方案）；②GitHub 存源码 + 阿里云做国内分发。
> v1 套壳方案已废弃，本版为现行方案。

## 一、UI 策略：原生桌面软件（页面不搬，资产抽包）

### 定位声明

不加载 `web/dist`，不做浏览器壳。桌面端渲染进程是**独立的桌面专属 UI 代码**，拥有完整的原生体验；与网页端的一致性通过**共享包**保证，而不是通过加载同一份产物保证。

### 与"套壳"的本质区别

| 维度 | 套壳（v1，废弃） | 原生（v2，现行） |
|------|----------------|----------------|
| UI 来源 | 加载 web/dist | 桌面专属 renderer 代码 |
| 断网行为 | 网页依赖云端 API，断网残废 | Local-first，断网全功能可用 |
| 窗口体验 | 浏览器式默认标题栏 | 无边框 + 自绘标题栏 + 托盘 + 全局快捷键 |
| 启动速度 | 受网页包体积影响 | 只打桌面需要的代码，秒开 |
| 一致性保证 | 天然一致（同一份产物） | 共享包单一来源，改一处两端生效 |

### 共享包体系（一致性 + 复用的正解）

把网页端"内容"抽成 monorepo 共享包，web 和 desktop 各自引用——这是"沿用网页端内容"和"真桌面软件"两个诉求的交点：

```
microbubble-agent/
├─ packages/
│  ├─ design-tokens/    # variables.css 单一来源（暖珊瑚色系/阴影/圆角/动效时长）
│  ├─ shared-types/     # 领域类型（实验/样本/稿件/任务…桌面已有 schema，反向输出）
│  ├─ api-client/       # 后端 API 封装（协作数据用，web 与 desktop 同款）
│  └─ ui/               # 高频复用组件（渐进抽取：Markdown 渲染、Diff 卡片、图表容器）
├─ web/                 # 引用 packages，网页端不受影响
└─ desktop/             # 引用 packages，renderer 全新桌面 UI
```

- `design-tokens` 第一步就做，成本极低：网页端 variables.css 移入包内，两端 import，视觉血缘立刻统一
- 组件按需渐进抽取：桌面 UI 重写某个页面时，把其中可复用的部分（如 RichBlockRenderer、TraceTimeline 这类展示组件）下沉到 `packages/ui`，网页端同步替换引用
- 引入 Element Plus（桌面 renderer 当前缺失），与网页端同栈，组件移植是"改进口"而非"重写"

### 桌面原生体验清单

1. **无边框窗口 + 自绘标题栏**：macOS 红绿灯 / Windows 最小化关闭，标题栏兼作拖拽区，与内容融为一体
2. **全局命令面板**：Ctrl+K 唤起（已有 ShellCommandPalette 雏形），搜索/跳转/执行动作/调 Agent
3. **系统托盘 + 原生通知**：任务提醒、会议提醒走 OS 通知中心（对应网页端通知面板的能力升级）
4. **全局快捷键**：截图标注、快速记录灵感
5. **多标签工作区 + 底部状态栏**：状态栏显示同步状态/当前模型/版本号
6. **文件关联与拖拽**：双击 .csv 直接进实验导入流；拖拽 PDF 进窗口即问即析
7. **登录一次长期有效**：token-vault 已有，配合开机自启（可选）做到"打开就用"

### 信息架构（重设计 renderer）

```
┌────────────────────────────────────────────┐
│ 自绘标题栏（搜索 / 窗口控制）                  │
├──┬─────────────────────────────────────────┤
│侧│  主工作区（多标签：对话 / 实验 / 稿件 / 知识）│
│边│                                          │
│栏│                                          │
├──┴─────────────────────────────────────────┤
│ 状态栏：同步状态 · 模型 · 工作区 · 版本         │
└────────────────────────────────────────────┘
```

侧边栏六项：AI 助手（Agent 对话+文件操作）、实验 ELN、稿件、知识库、会议、设置。现有复杂视图（AgentCenter/ResearchWorkspace 等）不保留原样，能力并入这六项。

### 数据架构：Local-first 分层（"真软件"的核心）

| 数据类别 | 主库 | 云端关系 | 断网行为 |
|---------|------|---------|---------|
| 本机科研数据（ELN 实验原始记录、稿件草稿、聊天历史、工作区文件） | 本地 SQLite + 文件系统 | 可选备份，本机为准 | **全功能可用** |
| 团队协作数据（任务、会议、知识大脑、成员） | 云端 PostgreSQL | 本地缓存 + 写队列，联网自动同步 | 可读，写操作排队 |

同步引擎（main 进程）：按表增量（updated_at 游标 + 版本号），冲突 last-write-wins + audit 留痕；协作数据写操作进持久化队列，联网重放。这是套壳永远做不到的——套壳断网即死，原生软件断网照用、联网自动补同步。

### 实施顺序

| 步骤 | 内容 | 量级 |
|------|------|------|
| N1 | monorepo 化（pnpm workspace）+ design-tokens 抽包，两端接入 | 小 |
| N2 | 无边框窗口 + 自绘标题栏 + 侧边栏/状态栏骨架 + Element Plus 接入 | 中 |
| N3 | 六大信息架构落位：AI 助手（含 FileAgentLoop 工具卡片）+ ELN + 稿件 | 中 |
| N4 | 命令面板 + 托盘 + 原生通知 + 快捷键 | 小 |
| N5 | 同步引擎（协作数据缓存/写队列 + 本机数据备份） | 大 |
| N6 | packages/ui 渐进抽包（与网页端替换引用同步进行） | 持续 |

现有 renderer 代码不推倒重来：布局骨架重做，但 services/stores/composables 大量可迁；重写聚焦在"原生体验层"（标题栏/托盘/快捷键/命令面板）和信息架构归位上。

## 二、发布通道：GitHub 存源码 + 阿里云国内分发（v1 结论不变）

**可行、更快、更本地化**。`electron-builder.yml:157-164` 已预埋双 provider（generic `releases.mnb-lab.cn/desktop` + GitHub）。

1. **GitHub Actions 构建** → 发 GitHub Release（源码/版本事实源 + 国际通道）→ 同一 workflow 用 ossutil 同步三件套（`latest.yml` + `.exe` + `.blockmap`，同版本一致）到阿里云 **OSS + CDN**，`releases.mnb-lab.cn` CNAME 过去，electron-updater feed 指向国内 CDN
2. **用 OSS+CDN，不用 ECS 直托**：2核2G 带宽 3-5Mbps，100MB 安装包直下要几分钟；OSS 流量费每月几块钱
3. **落地缺口**：electron-updater 接入（原 R7 占位）+ CI 加 ossutil 步骤（RAM 子账号 AK 进 secrets）
4. **签名注意**：无 CSC_LINK 阶段 `verifyUpdateCodeSignature` 临时降为 false，SmartScreen 警告可接受；长期建议 OV 代码签名证书
5. mnb-lab.cn 已备案，`releases` 子域名无需新备案

## 三、优先级建议

发布通道（改动小、立即受益）先行；UI 原生化按 N1→N6 推进，N1/N2/N4 见效快，N5（同步引擎）投入最大但决定"真软件"成色。

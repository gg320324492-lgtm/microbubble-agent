# MicroBubble Desktop Release Acceptance Report

This document is the master artifact of the **R7 formal release rehearsal**.
It is generated by `desktop/scripts/release/run-release-rehearsal.ps1` and
machine-validated against `desktop/tests/release/rehearsal-report.schema.json`.

## How to run

```powershell
cd <worktree-root>
powershell -ExecutionPolicy Bypass -File desktop\scripts\release\run-release-rehearsal.ps1 `
  -SnapshotDir C:\snapshots\snap-2026-08-26 `
  -PackagePath C:\snapshots\snap-2026-08-26\out.mbrp `
  -InstallerPath release\1.0.0\ScientificResearchOS-1.0.0-x64.exe `
  -ReportPath release\1.0.0\rehearsal-report.json
```

The script writes a JSON report. **All nine top-level fields must be present
and `passed`**. Any missing field or `passed: false` aborts the release.

## Report fields

| Field | Meaning | Source |
|---|---|---|
| `sourceSnapshot` | R2 NDJSON snapshot integrity | manifest SHA-256 + counts |
| `mbrpVerification` | R1 `.mbrp` package checksum | `Get-FileHash` on the .mbrp file |
| `importResult` | R4 clean import into fresh user-data | `MbrpImporter.importPackage` (delegated) |
| `offlineChecks` | R5 work items / meetings / files / conversations open after disconnect | UI smoke (delegated) |
| `backupRestore` | R6 backup round-trip | `BackupService.create` + `restore` (delegated to vitest) |
| `installer` | R6 installer install + launch | `verify-installed-app.ps1` |
| `webUntouched` | R0 release guard | `verify-web-unchanged.mjs` working-tree check |
| `signedBy` | Windows Authenticode signature | `Get-AuthenticodeSignature` |
| `releaseCommit` | Git commit being released | `git log -1 --format=%s HEAD` |

## Acceptance criteria

A release is **APPROVED** when:

1. All nine fields present (schema-valid).
2. `sourceSnapshot.passed === true`.
3. `mbrpVerification.passed === true`.
4. `importResult.passed === true` AND `filesWritten > 0`.
5. `offlineChecks.itemsOpened.length >= 4` AND every entry `passed === true`.
6. `backupRestore.passed === true`.
7. `installer.passed === true` AND `smokeLaunchPassed === true`.
8. `webUntouched.passed === true` AND `offendingPaths.length === 0`.
9. `signedBy.signed === true` AND `certificateThumbprint` non-empty.
10. `releaseCommit.passed === true` AND `sha` matches the commit on `main`.

If **any** criterion fails, the orchestrator must **STOP** and post the
JSON report to the desktop release channel. Do not proceed to public
delivery.

## Stage semantics

- **Source-locally verified** - snapshot manifest SHA, package SHA, installer
  SHA, Authenticode fingerprint, release commit subject are computed inside
  the script and recorded verbatim in the JSON.
- **Orchestrator-delegated** - clean import, offline item open, backup
  round-trip, installer smoke launch are out of scope for this script so it
  remains non-destructive and hermetic. The corresponding stages are
  populated with `passed: true` and a `reason` explaining the delegation.
  The orchestrator (CI / release driver) is expected to overwrite these
  stages before posting the report.

## Troubleshooting

### `webUntouched.offendingPaths` non-empty

The working tree contains pre-existing changes under `app/`, `web/`,
`alembic/`, `docker-compose*.yml`, `nginx/`, or `.env`. These changes
**must not** ship with the desktop release. Coordinate with the author
to either land them on `main` first, or stash them before the rehearsal.

### `signedBy.signed === false`

The installer is unsigned. This is acceptable for **dev builds** but
**not for stable**. The CI pipeline must inject a Windows code-signing
PFX via `CSC_LINK` + `CSC_KEY_PASSWORD`. See
`docs/desktop-migration/release-operator-runbook.md` for details.

### `offlineChecks.itemsOpened` < 4

The four mandatory historical research surfaces (work items, meetings,
files, conversations) did not all open after disconnect. Inspect the
`reason` for each failed entry.

### `sourceSnapshot.manifestSha256` mismatch

The on-disk manifest has drifted since the original R2 capture. Re-run the
snapshot exporter and regenerate the `.mbrp` package before retrying.

## Audit trail

Every successful rehearsal appends to `release/<version>/rehearsal-history.md`:

```bash
echo "$(date -Iseconds) | $(git rev-parse HEAD) | PASS" >> release/<version>/rehearsal-history.md
```

Failed rehearsals must also be recorded (with reason) for post-mortem.

# Phase 0 报告：重建成员 enrollment 声纹质心（2026-10-31）

> **一句话结论：Phase 0 不通过（FAIL）。**
> 「把 enrollment 从 1.5–8 秒短片段换成 ≥30 秒长段」在**现役嵌入模型**下
> **没有带来任何可测量的改善**；官方 3D-Speaker 配方（10 秒窗均值）与旧配方
> **逐段配对差 = −0.0002（95%CI [−0.0043, +0.0183]，含 0）**。
> 而任务书指定的「只取最长的一段连续发言」实测**显著更差**
> （+0.0712，95%CI [+0.0246, +0.2139]，3 胜 32 负）。
>
> 唯一显著变好的是**整段嵌入**（把整条连续发言作为一个 clip 嵌入）：
> 同人跨场距离 0.3975 → 0.3894，配对差 **−0.0144，95%CI [−0.0329, −0.0020]（不含 0）**，
> 11 人里 8 人受益。**但它不能直接进生产**——见 §5 发现 2。
>
> ⇒ **根因不是「enrollment 太短」，是「逐段绝对匹配 + 逐段嵌入」这个范式本身。**
> ⇒ 换代路线的重心应从 Phase 0 转到 **Phase 1（换模型）** 与 **Phase 1b（簇质心命名）**，

## 2. 素材与方法

### 2.1 连续发言段怎么来的

1. 取两份人工确认台账
   （[2026-10-13](../docs/voiceprint-confirmed-blocks-2026-10-13.json) /
   [2026-10-30](../docs/voiceprint-confirmed-blocks-2026-10-30.json)），
   剔除 `_可用=false` 与非人标签（视频 / 人群杂音 / 环境声 / 发言人?）⇒ **250 条人物块**。
2. **按 (人, 场) 把相邻块合并成连续段**（空隙 ≤ 0.75s 才合并 —— 更大的空隙是别人的话，不能吞）。
   台账块是「逐窗切分后的区间」，不合并就拿不到连续发言。
3. 保留 ≥15s 的连续段 ⇒ **162 条**（≥30s 的 111 条）。
4. 段内语音 = 该区间内**生产转录段**的音频拼接（去掉段间静音）；
   ⚠️ 段的中点落在区间内才计入 ⇒ 跨界的段不双算。

覆盖：19 人，**13 人跨 ≥2 场**（刘子煜 / 吴孟铨 / 宋洋 / 张宏魁 / 王书馨 / 王天志 /
肖佐林 / 胡小琪 / 蒋芦笛 / 赵航佳 / 陈天祥 / 陈金薪 / 韩重阳）⇒ 只有这些人才谈得上「跨场距离」。

### 2.2 五种建库口径（同一素材、不同切法）

| 口径 | 做法 | 对应问题 |
|---|---|---|
| `seg_old` | **旧口径**：该人在该场的**短段**（1.5–8s）嵌入取均值 | 现役生产质心的建法（**对照组**） |
| `c10` | 长段切 **10 秒窗**，各窗嵌入取均值 | 3D-Speaker 官方 recipe |
| `c5` | 长段切 **5 秒窗**，各窗嵌入取均值 | 中间档，用来量「窗长」这一个变量 |
| `whole` | 长段**整段**作为一个 clip 嵌入（多个长段则取均值） | 「直接整段嵌入」 |
| `c10_longest` | **只用该场最长的一条连续段**的 10 秒窗均值 | 任务书指定的配方 |

⚠️ **所有比较都在「共同单元」上做**：5 个变体共同拥有的 (人, 场) 单元共 **37 个**
（覆盖 19 人）；其中关小未 / 李胜景各只有 1 个单元 ⇒ 无跨场配对 ⇒
**实际参与跨场配对的是 35 对（17 人）**。
双指标测试段分母 **7731 段**完全一致 ⇒ 变体之间的差异**只可能来自建库方式**
（类 20.249 ⑧：先锁死输入，再谈差异）。

### 2.3 嵌入管线

- 现役生产路径 `VoiceprintService.batch_extract_embeddings`
  （`iic/speech_eres2net_sv_zh-cn_16k-common`，ERes2Net，192 维）。
- 实测 **0.052 s/段**（20 条 1.03s）⇒ 14145 条约 12 分钟，**全部一次性嵌入**，
  保证同源同状态（不复用 `/tmp/vp/all3.npz` 的旧缓存，避免「输入漂移」，
  类 20.249 ⑧）。
- MinIO 取音频**用完整对象键做缓存名**（类 20.242）；
  每场音频长度必须覆盖整场转录，否则**报错退出**（类 20.220）。

## 3. 🔬 探针实测：ERes2Net 对「音频长度」极其敏感（这是理解全部结果的关键）

| 探针 | 实测 |
|---|---|
| 2.3 s 段嵌入 | 0.052 s/段 |
| 整段嵌入 10 / 30 / 60 / 120 / 300 s | 0.06 / 0.11 / 0.18 / 0.32 / 0.87 s |
| 整段嵌入 **600 s** | **231.9 s**（相对 300s 是 **267 倍**的非线性爆炸） |
| 同一段 10s 音频 **+5s 静音** | 与基准余弦 **0.766** |
| 同一段 10s 音频 **+20s 静音** | **0.629** |
| 同一段 10s 音频 **+60s 静音** | **0.507** |

> ⚠️ **2026-10-31 Phase 1 订正（同日）**：上表的「长度敏感性」三行是用
> **随机噪声**当基准音频测的 ⇒ **基准本身不稳**，把降幅**夸大了**。
> 用**真实语音**复测（Phase 1 探针，10s 真实语音 + 尾部静音）：
> **ERes2Net 现役：+5s 0.944 / +20s 0.833 / +60s 0.658**；
> **ERes2NetV2：+5s 0.946 / +20s 0.826 / +60s 0.696**。
> ⇒ **方向不变（嵌入确实依赖音频总长度），但幅度比本表小**；
> 且「V2 并不更不敏感」⇒ §5 发现 2 的结论对两个模型都成立。
> ⇒ 本表的 0.507 / 0.629 / 0.766 **只应作为「噪声基线下的下界」**看待，
> **不要**当成真实语音上的数值引用。

⇒ **两点直接决定 Phase 0 的结论**：
1. **嵌入向量强烈依赖音频总长度**，不只是说话人。
   ⇒ 「长段质心」与「短段查询」**不是同一个表征空间**，直接比对会引入长度偏置。
2. **600 s 整段嵌入在工程上不可用**（232 s/条）⇒ 韩重阳 600 s / 陈天祥 398 s /
   蒋芦笛 318 s 三条最长段**未做整段嵌入**（`whole` 口径覆盖 37 而非 39 个单元）。

## 5. ⭐ 三个机制性发现（比结论本身更值钱）

### 发现 1：决定 enrollment 质量的是「素材条数 / 声学多样性」，**不是「单条有多长」**

| 口径 | 用了多少素材 | 同人跨场（配对差） | 生产口径逐段配对 |
|---|---|---|---|
| `c10_longest` 只用**最长一段** | 少（单条，声学上下文单一） | **+0.0712**（显著更差） | **+0.0213**（显著更差） |
| `c10` 用**该场所有**连续段 | 多（平均 223.6 s 语音 / 人·场） | −0.0002（无差别） | +0.0003（无差别） |
| `seg_old` 用该场**全部**短段 | 多（平均 185.5 s / 人·场） | 基准 | 基准 |

⇒ **任务书里「取其最长的一段连续发言」这条配方，实测是所有口径里最差的。**
原因与类 20.226 的「单场样本过拟合」同源、但更细一层：
**过拟合的单位不是「一场」，是「一段声学上下文」** ——
一条 600 秒连续发言只覆盖一个房间/一个麦克风位置/一个话题；
多条短段跨会议、跨房间、跨话题，**声学多样性更高**。
⇒ 今后任何 enrollment 重建，**必须跨多场、多条连续段采样**。

### 发现 2：`whole`（整段嵌入）是唯一显著的赢家，但它属于**另一个表征空间**

- 它在**质心↔质心**上显著更好（−0.0144，CI 不含 0，8/11 人受益），
  在**生产口径逐段配对**上也显著更好（−0.0048，CI 不含 0），
  判别间隔最大（0.2576 vs 0.2323），双指标净增益最高（+485）。
- **但 argmin 正确率从 88.4% 掉到 77.2%（−11.2 点）**。

机制（§3 探针直接给出）：**整段嵌入与短段嵌入不是同一个表征** ——
短段到整段质心的距离整体抬高（同人中位 0.2525 → 0.3021），
而异人距离几乎不动（0.4792 → 0.5007）⇒ **判别余量被压缩** ⇒ 逐段匹配大量撞车。

⇒ **`whole` 质心只有在「查询侧也是长段/簇质心」时才成立。**
这恰恰就是 **Phase 1b（diarization → 簇质心 → 簇质心命名）** 的形态。
⇒ **Phase 0 唯一的正面结果，是在给 Phase 1b 背书，不是在给现有逐段流水线背书。**

### 发现 3：任务书给的判据里，有一个**度量口径**陷阱

已发表的 0.5038 是**质心↔段**；任务书的「同人跨场距离」定义是**质心↔质心**。
在**质心↔质心**口径上，**旧系统本来就是 0.3975**（早就在 0.5038 以下）。
⇒ 若只按字面判「< 0.5038」，会得出「长段明显更好」的**错误结论**。
⇒ **正确对照物是同口径的旧系统**（0.3975），本报告所有配对比较都基于它。

## 6. 判定

判据（全部在共同单元 / 共同分母上）：

| 判据 | c10 | c5 | whole | c10_longest |
|---|---|---|---|---|
| **C1** 同人跨场显著低于基线**且**配对显著优于旧口径 | ✅（数值低于 0.5038，但配对不显著） | ❌ | ✅（配对显著更优） | ❌ |
| **C2** 异人互距不恶化 | ✅ | ✅ | ✅ | ✅ |
| **C3** argmin 正确率上升 | ❌ 87.5% < 88.4% | ❌ 87.3% | ❌ 77.2% | ❌ 82.0% |
| **C4** 双指标净增益 > 旧配对 | ✅ +57 | ✅ +12 | ✅ +485 | ❌ −1107 |
| **总判定** | **FAIL** | **FAIL** | **FAIL** | **FAIL** |

**Phase 0 = 不通过。** 理由（按重要性）：

1. **官方配方是统计上的无操作**：10s / 5s 窗均值与旧短段均值在**两条独立口径**上
   （质心↔质心配对 −0.0002；生产口径逐段配对 +0.0003）**都等于 0**，
   且 argmin 正确率反而略降（−0.9 点）。
2. **任务书指定的配方（只取最长一段）显著更差**，而且在**所有**指标上都差。
3. **在产生 0.5038 的那个测量上，四种长段口径全部更差**（0.5113–0.5291 vs 0.5038）。
4. 唯一显著变好的 `whole` 口径**不能进现有流水线**（argmin 掉 11.2 点）。

⇒ **「enrollment 太短是根因」这个前提，在现役嵌入模型下不成立。**

## 7. Phase 0 不通过 ⇒ Phase 1 / 1b 还有没有意义？

**有，而且 Phase 1 的优先级应当提高；但路线要重排。**

### 7.1 Phase 1（换模型 ERes2NetV2）—— **更有意义了，不是更没意义**

原来的排序理由是「换模型前必须先修好 enrollment，否则是拿坏质心做比较」。
**Phase 0 恰恰证明 enrollment 不是坏在「短」，而是这套嵌入对短段/长段的区分能力本身有限**
（10 秒窗与 5 秒窗与 1.5 秒段的质心，判别力几乎一样 ⇒ 换窗口不改变可分性）。
⇒ 于是**模型本身成了未被排除的、且最可能的主因**。

- ERes2NetV2 的短时长 EER 改善（2s：3.28% → **1.48%**，−55%）**正好打在我们所处的
  「短段逐段匹配」区间** ⇒ 与本项目当前形态**高度对口**。
- ⚠️ 但 Phase 1 的评测口径要改：**必须在「生产粒度（短段）」上评**，
  并用**现役生产质心**做基线（不是长段质心）—— 因为长段质心已被证明在短段查询下没有优势。
- ⚠️ 换模型后**全部成员质心必须重算**（两模型空间余弦 −0.1621，已在调研文实测）。

### 7.2 Phase 1b（簇质心命名）—— **Phase 0 的正面结果直接支持它，优先级应与 Phase 1 并列甚至更高**

- `whole` 口径证明：**一条连续发言的整段嵌入，比任何窗口均值都更「跨场稳定」**
  （0.3975 → 0.3894，配对显著，8/11 人受益）。
- 这正是 Phase 1b 需要的东西：**用长段/簇级对象去命名**，而不是用短段去匹配。
- Phase 1b 同时绕开发现 2 的坑：**两侧都是长段/簇质心 ⇒ 同一个表征空间 ⇒ 不掉 argmin**。
- 社区数据也支持（3D-Speaker recipe 在 AISHELL-4 上 DER 10.30%，靠的就是聚类 + 簇质心命名）。

### 7.3 建议的重排（供主指挥拍板）

| 顺序 | 内容 | 依据 | 成本 |
|---|---|---|---|
| **1** | **Phase 1（换模型）**：同一批 8–9 场 11358 段，ERes2Net vs ERes2NetV2 vs CAM++，**生产粒度**，双指标 | Phase 0 证明 enrollment 不是主因；短时长 EER 改善对口 | 1–2 天，零生产改动 |
| **2** | **Phase 1b（簇质心命名）**：VAD → 重叠滑窗 → 嵌入 → 聚类 → **簇质心↔成员质心**命名；两侧都用长段 | Phase 0 的 `whole` 正面结果 + 社区 DER | 数天 |
| **3** | 录入入口改造（≥30 秒连续 + **样本留档**） | **不是**为了修当前匹配，而是 ①可审计 ②TSE/簇质心路线的硬前置（类 20.230 社区结论） | 低 |
| ✗ | **不做**：用长段重建 enrollment 后替换现役质心 | Phase 0 实测：净增益 ~0，`c10_longest` 显著为负 | — |

⚠️ **但 Phase 0 的负结果并没有否掉「重建 enrollment」这件事本身** ——
它否掉的是「**在现役嵌入 + 现役逐段匹配架构下**重建 enrollment」。
若 Phase 1b 落地（查询侧变成长段/簇质心），**长 enrollment 立刻重新变得必要**，
而且那时的素材要求会更高（整段嵌入 > 300 s 不可用 ⇒ 需要切片策略或换模型）。

## 8. 限制与未做

1. **`whole` 覆盖不全**：韩重阳 600 s / 陈天祥 398 s / 蒋芦笛 318 s 三条最长段
   **未做整段嵌入**（232 s/条，工程不可用）⇒ `whole` 的 37 个单元少于 `c10` 的 39 个。
2. **`c10_longest` 的「最长」按连续段长度选，不是按语音秒数选**（两者几乎一致）。
3. **统计功效有限**：长段素材层面只有 13 人跨 ≥2 场；
   可做同人跨场配对的是 **17 人 / 35 对**。
   `whole` 的显著性主要靠王天志的 21 对（占 60%）拉起来的，
   但**逐人看是 8/11 人受益**，方向一致。
4. **未测**：降噪前端（ClearerVoice）、VAD 切窗策略、TSE（类 20.243 判定为前置条件不足）。
5. **未做**：把新质心灌进生产做 shadow evaluation（等主指挥拍板后再做）。
6. **未改任何生产表**（已用 SQL 回读验证）。

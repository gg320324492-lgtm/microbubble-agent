## v0.1.6-alpha（2026-09-19）

### UI 彻底换新——宣纸暖白设计语言（M7）
- **[M7] 全界面切换到「宣纸暖白」**（决策 U3）：主色由珊瑚橙系全面切换为**靛墨蓝 #3e5c76**；
  背景改为**米色纸感三级**（纸底 #f3eddf / 面板 #f9f5ec / 卡片 #fffdf7）；边框、文本、语义色
  （ok 松绿 / warn 棕金 / danger 朱砂）与纸感阴影（暖褐调）全部重定义；圆角基准 10px
- **[M7] 标题衬线化**：页面主标题与 h1/h2/h3 使用衬线字体栈（Georgia + 宋体回退），
  正文保持无衬线——阅读与写作场景更安静、书卷气
- **[M7] 登录页换新**：身份区由暖黑改为靛墨深阶，双栏布局与全部文案保持不变；装饰波纹改用纸色
- **[M7] Element Plus 主题覆盖**：新增独立覆盖文件 `assets/theme-paper.css`，把
  `--el-color-primary` 系 / `--el-border-radius-*` / `--el-font-size-*` / `--el-text-color-*` /
  `--el-bg-color` / `--el-fill-color-*` 映射到宣纸令牌，并对 button / input / dialog /
  messagebox（危险确认）/ table / switch / progress / tag 做组件级微调
- **[M7] 珊瑚橙残留全局清零**：登录页 / 按钮 / 滚动条 / 状态栏 LED / SideNav 选中态等
  全部出现点逐处切换；源码检索旧主色值（含 rgba 三元组）命中数为 0
- **[M7] 六模块一致性过检**：知识库 / 会议 / 实验 ELN / 稿件 / 设置 / AI 助手（对话流、
  工具卡片、思考面板、命令面板）+ SideNav + 登录页统一到宣纸语言

### 随车修复与门禁（M7）
- **[fix] 设置页滚动缺陷（M5-2 遗留）**：矮窗口下内容被直接裁切且无法滚动——`.shell-main`
  由 `overflow: hidden` 改为可滚；对话页保持内部独立滚动，不会出现双滚动条。
  已做 720p 最小窗口全模块滚动自查（设置页实测可滚：内容 2512px / 视口 834px）
- **[M7] CI 产物可运行性门禁**（M6-2 转办）：发布流水线新增 `smoke` 步骤——静默启动打包
  产物、走完首启注册（真实写入 SQLite）、用 CDP 断言状态栏版本号，跑不起来即 fail；
  覆盖主进程 → 原生模块 ABI → IPC → 渲染进程 → 版本一致性整条链
- **[M7] 版本两处同步校验纳入门禁**：发布流水线首步即校验 `package.json` ↔
  `src/shared/constants.ts`，不一致直接失败（R-1 类翻车防线）

## v0.1.5-alpha（2026-09-19）

### 自动更新——从「手动下载」到「提示即升」（M6-1）
- **[M6-1] 自动更新通道（electron-updater）**：启动 5 秒后台检查（不阻塞启动、失败静默）
  + 设置页「检查更新」手动入口；发现新版本弹系统通知（点击聚焦并跳设置页）+ 设置页展示
  版本与下载进度条；**全程不自动下载、不自动安装**——下载由用户点击、安装前二次确认
- **[M6-1] 设置页新增「关于与更新」区块**：当前版本、更新状态/进度、检查/下载/安装按钮、
  「自动检查更新」开关（默认开）
- **[fix] 打包态缺失 `app-update.yml` 导致更新下载失败**：electron-builder 配置补 publish 段，
  打包自动产出 app-update.yml 与 latest.yml
- **[fix] 未打包环境更新检查被整体跳过且伪装「已是最新」**：装配漏传 `forceDev` 使
  electron-updater 闸门关闭、不发任何请求却返回 null；现以纯函数统一装配决策（feed-config），
  跳过场景如实显示「更新检查不可用（开发环境）」

### 发布自动化与打包清账（M6-2）
- **[M6-2] CI/CD 自动化**：新增 `.github/workflows/desktop-release.yml`——推送 `v*` tag 或手动
  触发即自动跑门禁三件套 → 打包 → 生成 latest.yml → 创建 GitHub Release 并上传三件套；
  只构建 `apps/desktop`，仅用内置 GITHUB_TOKEN
- **[M6-2] 发布脚本 `scripts/release.mjs`**（本地与 CI 同一脚本）：版本两处同步校验、
  out/ 分批清理、latest.yml 自动生成并逐字段自校验——消灭手工补 latest.yml
- **[M6-2] 托盘图标资源化**：托盘改用 `icon.ico`（Windows 原生多尺寸，高 DPI 不再拉伸模糊），
  缺 .ico 时自动回退 `icon.png`
- **[M6-2] 退出自动备份密码迁移 safeStorage**：`backup.exitPassword` 由明文改为
  `safeStorage` 加密存储（读旧明文 → 加密覆盖 → 清明文，兼容无旧值），界面只回显掩码
- **[M6-2] OSS 快照列举支持分页**：`listObjects` 按 continuation token 循环翻页，
  修复快照数超过单页上限（1000）时列表截断丢数据；并加按 key 去重防服务端异常重复

## v0.1.4-alpha（2026-09-18）

### 备份与恢复——工作数据可带走（M5 收尾）
- **[M5-1] 备份与恢复**：全部工作数据（SQLite + 附件）一键打包为 AES-256-GCM 加密备份
  容器（.mnbbak），从任一容器完整恢复；恢复前自动保留当前数据快照（pre-restore 安全网）；
  设置页「备份与恢复」区块（密码保护、本地快照列表、危险确认恢复流程）
- **[M5-2] 云端备份（阿里云 OSS）**：零依赖手写 V1 签名，备份包上传/下载/列表/删除；
  快照列表合并展示本地+云端（来源标注，云端恢复自动先下载）；「备份后上传云端」「退出时
  自动备份」开关（默认关，10s 超时保护、失败不阻塞退出）；AccessKeySecret 经 safeStorage
  加密存储，界面不回显
- **[fix] 恢复密码输入框补缺（M5-1 遗留）；备份目录空值兜底；命令面板测试环境修复**
- **[fix] 托盘图标打包后路径失效（v0.1.3 起既有缺陷）**：打包态 `app.getAppPath()` 指向
  `app.asar`（内部不含 `resources/`），图标实际由 extraResources 落在

- **已知问题**：退出自动备份密码暂存于本机设置（下版迁移 safeStorage）；OSS 列表超 1000
  快照需分页（M6）；附件无类型白名单

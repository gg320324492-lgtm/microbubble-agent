### 4. 关键技术发现 (本次 redo 据实)

#### 类 20.146 — sendingSessions 非 reactive 暴露 production bug

`web/src/composables/chat/useChatStream.ts:239`:
```
const sendingSessions = new Set<string>()  // ❌ 非 ref()
```

`isCurrentSessionSending = computed(() => sendingSessions.has(sessionId.value))` (line 255):
computed 不刷新, 因为 sendingSessions 不是 reactive. Vue 3 不会自动追踪 plain Set mutation.

**实战影响**: 用户发送消息时, #chat-stop-btn 永远不显示 (sending 状态没法 reactive 传播),
stop generation 按钮实际上不可用.

**本任务测试 I2 处理**: 测试验证 ChatViewSSE 模板完整性 (send-btn / stop-btn DOM 元素
至少其一存在), 不擅自改 production code (类 20.143 派工 v6 §13.3 不擅自扩不擅自缩).

**留口**: W101+ 派工应修 sendingSessions → reactive(new Set()) 或 ref<Set<string>>.

#### 类 20.143 — FollowUpChips.vue production code bug

- 沿用前一版 spec 发现: `<Transition>` 含 2 个 v-if 子节点 (Vue 3.5 strict 编译期拒绝)
- 测试不能改 production code → 选 production build (dist/) 而非 vite dev
- 组件 idle 不渲染, C10 改验证 bot-bubble 容器存在 (test-mode wrapper)

#### 类 20.144 — SPA 静态 server 内嵌 spec, 不留 untracked helper

- 派工原版 (commit 4510eac6) 留 `spa-server.cjs` untracked 文件, peer 反馈违反 "worktree clean"
- 本次 redo 把 server 代码内嵌到 spec 文件 (`SPA_SERVER_INLINE` 字符串)
- `test.beforeAll` 用 `spawn('node', ['-e', SPA_SERVER_INLINE], ...)` 跑内联代码
- 无需任何外部 helper, worktree 始终 clean

#### 类 20.145 — listSessions API 期望 paginated envelope

- `chatHistoryApi.listSessions()` 实际期望 `{items: [], total, page, page_size}` 分页信封
- 派工原版 mock 直接返回 array, store 解析失败 → sidebar 显示 "暂无会话"
- SessionActions 测试 (C9/I6) 找不到 .session-item 元素 → 失败
- 本次 redo mock 返回正确信封 + 直接注入 localStorage `chat_sessions_v3__u1` 键

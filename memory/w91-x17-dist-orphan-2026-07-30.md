## §6 派工 v6 §5 反馈 — 类 20 沉淀

### 类 20.36 **复发** (原: "cherry-pick 改 deps 必重跑 `npm run build`")

W87-X-2 沉淀后**再次复发**, 且形态升级: 本次不仅 dist 未跟随重 build, 更暴露 **dist 是"只增不删"叠加** — 历史 build 产物 107 个陈旧 chunk 长期滞留 git。原铁律只覆盖"忘了 build", 未覆盖"build 了但旧产物没清"。

### 类 20.85 (新, 加固 20.36) — "dist 必 clean build, 守恒 = 单代产物"

1. **`npm run build` 前必 `rm -rf dist/`** — vite 默认 `emptyOutDir` 在 dist 被 git 跟踪时易被历史残留污染; 不清则多代 chunk 叠加, orphan 逐批累积。
2. **dist commit 必验单代** — `ls dist/assets/index-*.js | wc -l` 期望 **恰 1**; >1 即多代残留。
3. **orphan 守卫应升级为双向** — 现仅测 `actual - referenced` (orphan)。应同时断言 `referenced - actual` (**missing**, 真白屏因子)。本次 missing=0 但 brief 误以为 missing≠0, 双向断言可让报告**自证方向**。
4. **陈旧代按"整代"清理, 不按单文件** — 删 `index-be8f90c0.js` 只消 orphan 告警, 余 106 个同代 chunk 仍在。修法是 clean build 后整体替换。

### 类 20.86 (新) — "前提检测命令必须能区分'引入'与'修复'"

brief §步骤 2 用 `git log --grep "…RAGEvalPanel"` 判断修复是否合入, 却被**引入 bug 的 commit** 假阳性满足。
**铁律**: 判断"修复是否合入"必须断言**修复后的代码事实**, 而非 commit message 关键词:
```bash
grep -q "VideoPlay" web/src/views/admin/RAGEvalPanel.vue   # 断言产物, 非断言 log
```
同源: 类 20.29 (不可凭 hook 报告) / 20.30 (必精确断言 returncode) / 20.32 (必实测 base)。

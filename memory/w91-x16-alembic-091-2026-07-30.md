## 6. 派工 v6 §5 反馈 — 类 20.86 加固

### 类 20.86 "alembic test 锚点必随 PR 同步, 实测当前 head, 不凭 CLAUDE.md 历史"

**根因**:
- W90-X-3 改 `087 → 090` 是凭推断 (W88 PR 系列可能推到 090), 未实测当时 head
- W94 PR8 推 `091_add_kg_entity` 时, 仅改了 PR 系列测试 (`tests/rag/test_pr8_e2e.py:371`), **漏改** `test_pre_commit_hook_passes.py`
- W90-X-3 的 090 期望被 W94 PR8 推到 091 后, 该测试即错配, 持续到 W91-X-16 才发现

**教训**:
1. **alembic test expected_head 必须随每次 PR 同步** — PR 加新 migration 时, 必须 grep 所有 `tests/` 文件中相关 `expected_head` 字面量同步更新
2. **改 expected_head 前必须实测当前 head** — `python -c "from alembic.config import Config; ..."` 实测, 不可凭 CLAUDE.md 历史推断 (类 20.29 + 20.32 同源, 实际场景教训)
3. **不改 CLAUDE.md 锚点字面量** — 任何 `expected_head = "087_..."` 都是技术债, 应改为 `head = s.get_heads()[0]` 动态断言 (本次未实施, 留 W92+ backlog)

**类似事故链** (派工纪要派生):
- W84 → W85 hotfix `085_billing_payment_tables` 加 `087_add_knowledge_original_parent_id` 时漏改测试期望 (W85 D-1 据实 6/13 测试用 `==` 字面量)
- W90-X-3 → W94 PR8 同样漏改 (`087 → 090` 没跟到 `091`)
- W83 D-2 锚点范式收口时 `expected_head` 字段还在, 但随每次 alembic 串单链都需手动同步, 极易遗漏

### 类 20.86 5 条铁律

1. **实测当前 head** — 改 expected_head 前必跑 `python -c "from alembic.config import Config; from alembic.script import ScriptDirectory; c=Config(); c.set_main_option('script_location','alembic'); s=ScriptDirectory.from_config(c); print(s.get_heads())"`, 不可凭 CLAUDE.md 历史
2. **grep 全 tests/** — PR 加新 migration 时必 `grep -rn "<旧 head>" tests/` 同步所有引用
3. **PR commit 必须含 head 同步** — PR merge checklist 加 "alembic test expected_head updated"
4. **冷缓存必跑** — 任何 expected_head 改动必须冷缓存 (`rm -rf alembic/versions/__pycache__ tests/alembic/.pytest_cache`) 跑一遍, 避免 `__pycache__` 残留老 head
5. **不长期保留字面量 expected_head** — 长远看应改为 `head = s.get_heads()[0]` 动态断言 + `assert head == "<current>"` 仅在测试首次生成时硬编码, 后续 PR 改 migration 时一并改; 当前留 W92+ 调研

## 4. 派工 v6 §5 反馈 类 20.63 新增

> **类 20.63**: "Playwright 软断言改硬门禁必 TEST_TOKEN 真注入 + throw if missing"

P-11 写的 dark-accent + el-menu-hover spec 用 "报告型" 软断言 (axe 跑完 + console 打
violations + 仅 `expect(Array.isArray(violations)).toBe(true)` 报告存在性), 在 TEST_TOKEN
缺失时:

- dark-accent 走 axe /login 页 (变量 css 部分仍生效, applied 偶有值), 看似 "90 PASS" 实则
  假绿 — 不在真正目标页
- el-menu-hover 走 "router 守卫重定向 → sidebar 不可见 → 跳过 hover 触发" 软降级, 看似
  "20 PASS" 实则没 hover 到 el-menu-item

**硬门禁 4 条铁律 (W89-X-11 沉淀)**:

1. **`test.beforeAll` 必 throw new Error if TEST_TOKEN 缺失** — 不允许软降级, 错误信息
   必含 TEST_TOKEN 注入命令 (curl /auth/login + python json)
2. **injectAuth 返回 false 必 throw** — 不允许 "authed=false → 继续跑" 的假绿
3. **data-theme / data-accent 必与预期一致** — 不允许 null / 错配 (硬门禁下 auth 已保证,
   router 不会再 redirect, 此处必为预期值)
4. **P-11 软断言注释必须删** — `// 报告型: 若 router 守卫把 /chat 重定向到 /login, sidebar
   不存在则跳过 hover, axe 仍扫 (扫的是登录页), 但不强行 hover 不存在的节点.` 这类
   软降级注释必删, 改写硬门禁注释 (抛错 / 真触发 / 明示 skip)

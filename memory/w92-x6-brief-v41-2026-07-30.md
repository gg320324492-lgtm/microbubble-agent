## 5. 6 必读段整合

1. **base ref 实测（20.46 / 20.32）**：local main 与 origin/main 均取 hash、subject、时间；结束再测漂移。
2. **branch/hash 实测（20.47）**：`show-ref` + `git log -1` + `git show --stat`；MISSING 即暂停。
3. **suite 路径探测（20.97）**：先 EXIST/MISSING 对表，再运行实存套件。
4. **merge 假阳性拦截（20.98）**：ahead=0 可能是空分支，必须交叉验证预期 commit/产物。
5. **收官 6 步（20.108）**：suite、ref、完整摘要、dev server、base、测试副作用。
6. **推断先验证（20.109）**：API grep + probe 红灯 + 真修前证据。

### 类号冲突处理

历史分支中相同类号存在语义冲突，例如 20.85 曾用于 dist clean build，W91-X-18/W92-X-4
又用于 helper fail-loud；20.86 也有“检查修后事实”和“alembic 锚点同步”两种记录。
v4.1 不删除任一历史教训，而是：

1. 类号只作为索引；
2. 派工 brief 必须同时写一句完整纪律；
3. 实战来源必须给 ref/hash/path；
4. 冲突时两条纪律并存，不以较新编号覆盖旧事实。

派工 v6 §5 反馈类 20 采用“累计 113+”历史台账口径，但该值不可由类号推算，
也不能为了对齐累计数伪造不可证实例。

## 7. v3 双锚定实战升级

v4.1 强制 8 项：

1. 实测预期 commit hash + message；
2. 实测预期 branch，或明确“待创建”；
3. local/remote base ref + 时间；
4. 绝对 worktree path；
5. allow/deny 到具体文件/函数/行号；
6. 路径已存在且 case 总数可核对的 smoke command；
7. 每个预期冲突的 ours/theirs/手工选择；
8. base/ref/path/推断/冲突/边界任一不成立即报告暂停。

分支名和 hash 独立验证；若 cherry-pick/rebase 改 hash，以 patch-id、commit message 与修后代码事实交叉核对。

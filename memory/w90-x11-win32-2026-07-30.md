## 5. 派工 v6 §5 反馈 — 类 20.93 新增 (本任务沉淀)

**类 20.93 (新增)**: 视觉回归 baseline 必与 CI runner 平台一致 (避免 win32 baseline 在 Linux CI 跳过 / 入主仓库后 0 消费)

四个子条款 (X-10 + W89 grand closure 误列 实战支撑):

1. **baseline 平台 suffix 必与 CI runner 平台一致** — Playwright 按 `{name}-{project}-{platform}.png` 找 baseline. Windows 产 `-win32`, CI Linux 找 `-linux` → 必 FAIL. 入 git 前必查 `ls | grep <ci-platform>`; 跨平台不可共用, 本地 dev baseline 与 CI baseline 是两套东西. (与类 20.62 子条款 3 同源, 本任务再强化为"必与 runner 一致"的硬门禁)
2. **CI 永久 `if: false` 跳过 = baseline 即使入 git 也 0 消费** — `lint-css.yml: visual-regression-deprecated: if: false` 永久跳过. 22 张 baseline merge 进 main = 仓库膨胀 + 写放大, 不入 CI 消费就别入 git. 类比: 数据库索引建了不用 = 写放大, baseline 入库不用 = 历史坑复发风险.
3. **grand closure 报告必真验证 "已 merge" 而非 "已 commit"** — W89 grand closure (`9e3722f86`) 误列 `075655736` 为"已收" (snapshots only), 实测 `git merge-base --is-ancestor` → NOT in main. 自报-实测背离是 W89 派工前提错配的隐形表现. 整改: grand closure 报告必加 "merge 时点" + "实测 ancestor" 段 (类 20.46 实战模式, W88-D-1 调研方法).
4. **历史废弃决策必查 `git log --diff-filter=D` + CI `if:` 条件** — X-10 重生成前未查 `f08e18584` 删 baseline png 根因 + `5522ad5a8` v76 废弃理由 → 复现历史坑. 调研报告必含 "废弃史 + 复发风险" 段, 不是只看"缺什么补什么" (类 20.62 子条款 4 强化).

**既有铁律实战命中** (本任务调研路径):
- **类 20.32 "base 必实测 ls-remote origin"** — 实测 `034343f8a` 与本地一致, 守恒.
- **类 20.46 "文档校核 4 段: grep / 实际数字 / 不擅自扩 / 留口"** — W88-D-1 调研方法复用, 派工 brief 假设与实测的 6 项校核.
- **类 20.62 "visual baseline 重 sync 必逐 spec + 统一 canonical project + 拍板"** — X-10 沉淀, 本任务确认其子条款 3 (平台 suffix) + 子条款 4 (废弃史) 在 W89 派工中未遵守 (这是治理冲突根因).

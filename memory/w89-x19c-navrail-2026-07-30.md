## 2. 真实 NavRail 契约 (2026-07-30 据实)

### 2.1 模板结构

```html
<nav class="nav-rail" :class="{ collapsed, 'mobile-open': mobileOpen }"
     aria-label="主导航" data-testid="nav-rail">
  <div class="nav-rail-brand">
    <span class="brand-icon" aria-hidden="true">MNB</span>
    <span v-if="!collapsed" class="brand-text">微纳米气泡</span>
    <button class="mobile-close" type="button" aria-label="关闭导航" @click="closeMobile">
      <el-icon><Close /></el-icon>
    </button>
  </div>
  <ul class="nav-rail-items">
    <li v-for="item in items" :key="item.path" class="nav-rail-item"
        :class="{ active: isActive(item.path) }">
      <router-link :to="item.path" :aria-label="item.label" :aria-current="..."
                   :data-route="item.path" @click="closeMobile">
        <span class="nav-icon"><el-icon><component :is="item.icon" /></el-icon></span>
        <span v-if="!collapsed" class="nav-label">{{ item.label }}</span>
        <span v-if="!collapsed && isActive(item.path)" class="active-mark" />
      </router-link>
    </li>
  </ul>
  <button class="collapse-btn" @click="uiStore.toggleNavRail()">
    <el-icon><component :is="collapsed ? Expand : Fold" /></el-icon>
    <span v-if="!collapsed">收起导航</span>
  </button>
</nav>
<button v-if="props.mobileOpen" class="nav-rail-scrim" @click="closeMobile" />
```

### 2.2 6 路由项 (W72 B-1 据实)

```typescript
const items: NavItem[] = [
  { path: '/chat', label: '对话', icon: ChatDotRound },
  { path: '/knowledge', label: '知识库', icon: Collection },
  { path: '/drive', label: '网盘', icon: FolderOpened },

  { path: '/meetings', label: '会议', icon: Microphone },
  { path: '/workspace', label: '项目', icon: DataBoard },

```

> 注意: 无 `/hypotheses` + `/settings` 项 (spec 旧版 router 配置含 9 路由, 实际 NavRail 仅 6 项).

### 2.3 主题机制 (W72 B-1 据实)

```javascript
// useThemeStore.js watch mode + accent → 写 document.documentElement
function applyTheme(mode, accent) {
  document.documentElement.setAttribute('data-theme', mode)       // 'light' | 'dark'
  document.documentElement.setAttribute('data-accent', accent)    // 'orange' | 'ocean' | 'forest'
}
```

> `data-theme-accent` 这种 `accent-{name}-{light|dark}` 模式**不是 HTML 属性**, 是 CSS 选择器模式, 仅在 `variables.css` 出现. spec 旧版误以为 nav 元素有此属性.

### 2.4 mobile drawer 模式 (W72 B-1 据实)

- NavRail 是**子组件**, `mobileOpen` 通过 `defineProps` 接收父级 v-model
- `update:mobileOpen` emit 是 v-model 桥梁
- `mobile-open` class 控制 drawer 显隐 (`transform: translateX(0)`)
- 父级 (App.vue 或 Layout) 持有 mobileOpen ref, 通过 @media (max-width: 767px) 控制
- **NavRail 内部不持有 mobileOpen 状态**, 真实实现是单向数据流

### 2.5 mobile-close 按钮可见性

> ⚠️ **重要**: `.mobile-close` 按钮**始终在 DOM 中**, 不是 v-if. CSS @media (max-width: 767px) 控制 `display: grid / none` 切换. spec 旧版假设"桌面端不应有 mobile-close"是错误, 实际 DOM 始终存在.

## 3. 修法 8 scenarios (类 20.74 实战)

### 3.1 修法策略

派工 v6 §5 反馈类 20.74 沉淀: **spec 适配 component 真实契约, 不动 production code**.

理由:
- component 是产品代码, 改 component 会破坏设计 (data-theme 走 document 而非 nav 元素是 v77 P2.6 决策, 不可逆)
- spec 是测试代码, 应反映当前真实契约
- 修 spec 1 文件 vs 改 component 5 处 (class + attr + button + emit + slot), 风险差异巨大

### 3.2 8 scenarios 修法对照

| Scenario | 修法 (spec 改动) |
|----------|-------------------|
| 1 | `findAll('.nav-item')` → `findAll('li.nav-rail-item')`; 删 `data-theme-accent` 断言; 改断言 `data-testid="nav-rail"` + `aria-label="主导航"` |
| 2 | 改用 `a[data-route="/chat"]` 定位 + `element.closest('li.nav-rail-item').classList.contains('active')` 验证 active class + `aria-current="page"` 验证 |
| 3 | 删 `#nav-rail-accent` 按钮查找; 改用 `themeStore.setAccent()` API 验证 store 状态 + `document.documentElement.getAttribute('data-accent')` |
| 4 | 改用 `document.documentElement.getAttribute('data-theme')` + `data-accent` 两个独立属性断言 6 组合 |
| 5 | `#nav-rail-hamburger` → `button.mobile-close`; 改用 `aria-label="关闭导航"` 验证; nav class 断言改为 `not.toContain('mobile-open')` (mobileOpen prop 默认 false) |
| 6 | `hamburger.trigger('click')` → `mobileClose.trigger('click')`; 验证 `wrapper.emitted('update:mobileOpen')[0]` 等于 `[false]` |
| 7 | 同样 `update:mobileOpen` emit 验证, 不再测 `drawer-open` class |
| 8 | 桌面端: `not.toContain('mobile-open')` + `button.collapse-btn` 存在; 移动端: `button.mobile-close` 存在 + `aria-label="关闭导航"` |

## 5. 派工 v6 §5 反馈 — 类 20.74 沉淀 (NEW)

> **类 20.74** "vitest stale slice 修法: 调研真实契约 + spec 适配 component (非反过来)"
>
> 实战场景: W89-X-13 据实报告 8/8 failed. 根因不是 component bug, 是 spec 引用旧契约 (`.nav-item` / hamburger / `data-theme-accent` 等), 与 W72 B-1 重构后的 NavRail.vue 真实契约不一致.
>
> 修法:
> 1. **先调研 component 真实契约** (grep class / attr / id / 事件 / prop / emit), 不信 spec 自报
> 2. **逐 spec 改 selector 适配真实契约**, 不动 component (component 是产品代码, 改 component 破坏设计)
> 3. **加 e2e 加固** 防止 spec 再次引用 stale selector (用 sentinel string + 真跑 vitest)
>
> 纪律:
> - ❌ 改 component 加旧契约 = 破坏设计 (v77 P2.6 data-theme 走 document 决策不可逆)
> - ❌ 删 spec = 失去回归保护
> - ✅ 改 spec + 加固 e2e = 最小风险 + 永久保护
>
> 8 scenarios 修法耗时: 调研契约 5 min + 改 spec 1 file 8 min + 加固 5 test 5 min = 18 min, 0 production code 改动.

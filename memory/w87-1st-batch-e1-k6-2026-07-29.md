## 3 脚本阈值选择理由

### 1. `chat_stream.js` — POST /api/v1/chat/stream (SSE)

- **VU**: 10 (LLM 流式响应 VU 不宜过多, 单 VU 独占 SSE 连接).
- **p95 < 5000ms 主门禁**: LLM 流式响应生产基线 p95 ≈ 3.2s (W72 第 2 批 D-1 真实施沉淀), 5000ms 留 1.5x 安全余量 (冷启动 + 工具调用 overhead).
- **p95 < 1500ms first-byte**: SSE TTFB 应接近 HTTP TTFB (< 500ms 正常, 1500ms 视为 LLM 冷启动).

### 2. `ws_notifications.js` — WS /api/v1/ws/notifications

- **VU**: 10 (长连接池, VU=连接数).
- **p95 < 1000ms message latency**: WS 通知本质是 server push (5s ping + 实时 activity/mention), 无 LLM overhead. 1s 阈值覆盖网络抖动 + Redis pub/sub 延迟.

### 3. `drive_collab.js` — WS /api/v1/drive/files/{id}/collab (Yjs)

- **VU**: 5 (协同编辑高开销, VU 太多拖垮 dev server; 5 VU 模拟 1 个 file_id 多端协同).
- **p95 < 500ms event delivery**: 协同编辑用户体验敏感, 500ms 以上开始感知延迟 (Google Docs 同类指标).
- **p95 < 800ms init snapshot**: snapshot 是 base64 全量, 略宽于普通 event.

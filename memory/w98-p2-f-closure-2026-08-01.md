### F2: 抽公共后老测试桩需要 alias 兼容
- 老 `tests/test_session_context.py` (19 case) 引用 `mba._ensure_session_context` / `mba._fetch_pg_messages` 等私有函数
- 抽公共后私有函数全删, 但生产代码仍 `await _ensure_session_context(...)` 调用, 因此在 agent 模块添加 5 个 alias import (`from app.services.session_context import _fetch_pg_messages, _get_last_pg_id, ... as _xxx`)
- 测试 patch 路径需从 `patch.object(mba, "_fetch_pg_messages", ...)` 改为 `patch("app.services.session_context._fetch_pg_messages", ...)`, 因为生产代码用的是 `session_context` 命名空间
- 测试 `session_manager` patch 同理 — 改为 `patch("app.services.session_context.session_manager", ...)` (因为 `from X import Y` 创建本地 binding)
- 处理: 8 处老测试失败 → 0 处失败 (派工 v10 §3 据实上报沉淀)

### F3: 测试 `_set_last_pg_id` 直接替换 mba 属性的 pattern 在抽公共后失效
- 老测试 `test_chat_stream_done_emits_message_id` 写 `mba._set_last_pg_id = AsyncMock()` 直接替换
- 抽公共后 `_set_last_pg_id` 是 alias, 设置 mba 模块属性仍然有效 (alias 本身就是引用)
- 但测试中同时 patch `app.services.session_context.set_last_pg_id` 不拦截 (生产代码走 agent 模块的 alias)
- 处理: 移除 `patch("app.services.session_context.set_last_pg_id", AsyncMock())` 改为 `mba._set_last_pg_id.assert_awaited_once_with(...)` (直接断言 alias)

### F4: `from X import Y` 命名空间语义影响 patch 路径
- 派工 §6 据实上报铁律沉淀: **patch 必须针对函数实际定义的模块**, 不能针对 re-export 模块
- 例: `_ensure_session_context` 实际定义在 `app.services.session_context`, 即使 agent 通过 alias 暴露 `mba._ensure_session_context`, 生产代码走的是 `session_context._ensure_session_context`, patch 必须打 `app.services.session_context._ensure_session_context`

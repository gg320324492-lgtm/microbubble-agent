## 3. 关键决策: 为什么**否决** `npm audit fix`

派工 brief 步骤 4 选项 A 建议先跑 `npm audit fix --legacy-peer-deps`. **实测否决**, 据实上报:

```
npm audit fix --package-lock-only
→ 92 vulnerabilities (68 moderate, 23 high, 1 critical)
→ 95 vulnerabilities (66 moderate, 28 high, 1 critical)   ❌ 反而恶化
```

- **high 23 → 28 (+5)**, total 92 → 95 (+3), critical 纹丝不动
- 根因: `npm audit fix` 把部分传递依赖升到**新 major**, 新 major 自身携带新 advisory, 净效应为负
- 处理: `git checkout package-lock.json package.json` **完整回滚**, 复测确认回到 92 基线后, 改走 overrides 单点修复 (brief 选项 B)

> **brief 前提偏差 2 处 (据实上报, 不擅自扩)**:
> 1. brief 称 "`--legacy-peer-deps` 是因为本项目 react 19 + vue 3 混合" — **本项目 `web/package.json` 无任何 react 依赖**, 纯 Vue 3 栈. 该 flag 无实际必要, 未使用.
> 2. brief 步骤 5 示例断言 `summary["high"] == 0` 写在 `test_modern_summary` 里与 `test_no_high_vulnerabilities` 重复; 实测重构为职责分离的 5 个用例.

## 4. `overrides` 不能覆盖直接依赖 (npm EOVERRIDE)

首版 overrides 含 `axios` / `postcss` / `vite` 三个直接依赖, `npm install --package-lock-only` 直接报错:

```
npm error code EOVERRIDE
npm error Override for axios@^1.6.2 conflicts with direct dependency
```

**npm 语义**: `overrides` 只能作用于**传递依赖**; 直接依赖必须改 `dependencies` 声明本身. 由于三者 `^` 范围已覆盖安全版本, 最终解法是 `npm update axios postcss vite --package-lock-only` — **零 package.json deps 改动**, 完美守住派工边界.

## 7. 派工 v6 §5 反馈 — 类 20.35 沉淀

> **类 20.35**: **npm audit 必须 high/critical 硬门禁, moderate 留 overrides 兜底**
>
> 1. **门禁只卡 high + critical** — moderate/low 数量受上游 advisory 发布节奏影响持续漂移, 纳入门禁必然频繁误红, 阻塞无关 PR
> 2. **`npm audit fix` 必须先 `--dry-run` + 实测校核, 不可盲信** — 本次实测 **92 → 95 恶化 (high +5)**. 自动修复会跨 major 引入新 advisory, **净效应可能为负**
> 3. **`overrides` 仅对传递依赖生效** — 直接依赖会报 `EOVERRIDE`, 须改 deps 声明或用 `npm update` 走 semver 范围内升级
> 4. **优先 `npm update` 而非改 deps 声明** — 若 `^` 范围已含安全版, `npm update` 可在**零 package.json deps 改动**下清零漏洞, 完美守住 "0 production code" 边界
> 5. **级联 high 无需逐个处理** — "depends on vulnerable versions of X" 类 high 会随 leaf 修复自动消失 (本次 11/23 属此类), **不要为它们接受破坏性 major 降级**
> 6. **门禁必须反向验证** — 删掉修复项复跑确认 FAILED, 否则无法区分"真绿"与"断言写错的假绿"

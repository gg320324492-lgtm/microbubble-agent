## 2. 修法: exclude 而非 include

### 2.1 派工 v3 双锚定备选 (主指挥决策)

**选项 A — 改 include 超严格** (派工 v3 警告):
```javascript
testMatch: [
  /tests\/visual\/(desktop|mobile|local-only|desktop\/comments|mobile\/comments)\/.*\.spec\.mjs$/,
]
```
- ❌ 风险: 未来加新 spec 目录 (如 `tests/visual/admin/`) 必须更新 include list
- ❌ 否则漏 spec (silently miss)

**选项 B — 加 exclude 段** (主指挥派工 brief 选择):
```javascript
testMatch: /tests\/visual\/.*\.spec\.mjs/,
exclude: [
  /tests\/visual\/a11y\/.*\.spec\.mjs$/,
  /tests\/visual\/e2e\/.*\.spec\.m?js$/,
  /tests\/visual\/pwa\/.*\.spec\.mjs$/,
],
```
- ✅ 优点: 未来加新 spec 目录只需加一行 exclude
- ✅ 优点: 显式排除法 (显隐枚举)
- ✅ 优点: 跟 a11y 专属 config 隔离明确

### 2.2 实际改动 (commit 待)

`web/playwright.config.js` 顶层加 exclude 段:

```javascript
testMatch: /tests\/visual\/.*\.spec\.mjs/,
// W89-X-23 (派工 v3 § 反馈 类 20.78): 用 exclude 而非 include 收窄 testMatch
// 根因: 宽 testMatch + 5 project 重复匹配同 spec 导致 113 baseline 重复
// (61 张独立 baseline × 重复匹配). 排除 a11y/e2e/pwa 后:
//   - a11y: 有专属 config (tests/visual/a11y/playwright.a11y.config.mjs)
//   - pwa:  也用专属 config 路径 (未来 W87-P-3)
//   - e2e:  W89-P-10 移到 tests/visual/e2e/ (comprehensive 端到端不需要 baseline 对比)
// 用 exclude (而非 include) 更安全: 未来加新 spec 目录只需加一行 exclude, 不会漏 spec
exclude: [
  /tests\/visual\/a11y\/.*\.spec\.mjs$/,
  /tests\/visual\/e2e\/.*\.spec\.m?js$/,
  /tests\/visual\/pwa\/.*\.spec\.mjs$/,
],
```

### 2.3 项目级 testMatch 未改 (留给 W89-X-24+)

考虑到严格边界 — 不动 spec 文件, 不动其它 project 配置,
项目级 testMatch 收窄 (例如 desktop-chrome 排除 recording-*) 留 W89+ 后续:

未来派工 brief v3 中应建议:
```javascript

  name: 'desktop-chrome',

```

## 5. 派工 v6 §5 反馈: 类 20.78 新增

### 5.1 类 20.78 实战沉淀

**类 20.78**: "playwright.config.js testMatch 收窄必用 exclude 而非 include, 排除 e2e/a11y/pwa"

**实战细节** (W89-X-23):

1. **顶层 testMatch 不宜改为超严格 include**
   - 风险: 未来加新 spec 目录 (如 `tests/visual/admin/`) 必须更新 include list
   - 否则漏 spec (silently miss) — 比重复匹配更难发现
   - 实战: a11y 已有专属 config, 若顶层 include 漏 `a11y/`, 主 config 仍可能误匹配

2. **顶层 exclude 段必须明确排除专属 config 路径**
   - `tests/visual/a11y/` — 已被 `tests/visual/a11y/playwright.a11y.config.mjs` 收
   - `tests/visual/pwa/` — 未来 W87-P-3 PWA spec 用专属 config
   - `tests/visual/e2e/` — W89-P-10 综合 e2e 不需要 baseline

3. **项目级 testMatch 收窄 留未来派工**
   - desktop-chrome vs harmonyos-arkweb 重复匹配 recording-* 需项目级 testMatch 收窄
   - W89-X-23 范围限定: 仅顶层 exclude, 不动 project 级 (避免扩大改动面)
   - W89+ 派工 brief: 给项目级 testMatch 加 `((?!recording-).)*` 负向预测

4. **e2e 加固 必含 3 类守护**
   - 项目存在 (test_playwright_config_exists)
   - 必含关键词 (test_testmatch_excludes_e2e/a11y/pwa) — 简单 grep 守护更稳定
   - 形式必为 exclude 而非 strict include (test_testmatch_is_exclude_not_strict_include)

# W100 +53 plan-done SSE 事件补全 — root cause + 修复

## 背景

W100 +52 在 PlanSteps.vue 加了 auto-collapse 逻辑：默认模式下，全部 step done 后自动折叠成单行摘要 "✓ 计划完成: N 个步骤"。
但部署后实测 auto-collapse 永不触发，用户看不到折叠效果。

## Root Cause（实测）

`PlanSteps.vue:73-82` 的 auto-collapse watcher 依赖 `doneCount === total.value` 触发。
但前端 `useChatStream.ts:835-843`（W100 +53 之前）的 plan_step 事件处理只 push 不 dedup：

```ts
case 'plan_step': {
  if (!currentAssistant.plan) currentAssistant.plan = []
  currentAssistant.plan.push({
    step: evt.step || evt.label || '',
    tool: evt.tool_name,
    status: evt.plan_status || 'pending',
  })
  break
}
```

后端 `app/agent/agentic_loop.py`（W100 +53 之前）的 plan_step emit 序列：

```python
yield StreamEvent(type="plan_step", step="phase0_plan", plan_status="pending", ...)  # 1
yield StreamEvent(type="plan_step", step="phase0_plan", plan_status="running", ...)  # 2
# 每个 tool:
yield StreamEvent(type="tool_use", ...)                                                # 3
yield StreamEvent(type="tool_result", ...)                                             # 4
# (从不在 tool_result 后发 plan_status="done"!)
yield StreamEvent(type="plan_step", step="phase0_plan", plan_status="done", ...)       # 5 (post-loop, 无 tool_use_id)
```

每条 plan_step 都 push 新 step → plan 数组累积 5 行，status 分别是 `pending`/`running`/`running`/`running`/`done`，
doneCount = 1，total = 5 → `newVal === total.value` 永不满足 → auto-collapse 永不触发。

## 修复（W100 +53 3 commits）

### W100 +53a（commit `e9dd43663`）— 后端 SSE 协议补全

`app/agent/agentic_loop.py`：每个 tool_result 后 yield 1 个 `plan_step done` 事件，**带 tool_use_id**（与对应 tool_use 一致）：

```python
yield StreamEvent(
    type="plan_step",
    step=tool_name,
    tool_name=tool_name,
    tool_use_id=tool_use_id,  # 关键: 前端按 id 去重
    plan_status="done",
    label=f"✓ {tool_name}",
)
```

同时移除 post-loop 的 `phase0_plan done` 孤儿 yield（无 tool_use_id 匹配，会 push 新行），阶段完成 summary 改走 `thinking` 事件（前端 toolTrace 显示，不污染 plan 数组）。

### W100 +53b（commit `da84656`）— 前端 dedup by tool_use_id

`web/src/composables/chat/useChatStream.ts:835-862`：收到 plan_step 事件时按 tool_use_id 查找 plan 数组中已有 step，原地更新 status：

```ts
case 'plan_step': {
  if (!currentAssistant.plan) currentAssistant.plan = []
  const incomingToolId = evt.tool_use_id || evt.tool_name
  if (incomingToolId) {
    const existingIdx = currentAssistant.plan.findIndex(
      (s) => s.tool_use_id === incomingToolId ||
             (!s.tool_use_id && s.tool === incomingToolId),
    )
    if (existingIdx >= 0 && evt.plan_status) {
      const next = [...currentAssistant.plan]
      next[existingIdx] = { ...next[existingIdx], status: evt.plan_status }
      currentAssistant.plan = next
      break
    }
  }
  // 老消息兼容: 无 tool_use_id → fallback push
  currentAssistant.plan.push({ ... })
  break
}
```

PlanStep interface（useChatStream.ts:126 + PlanSteps.vue:30）新增 `tool_use_id?: string` 字段，向后兼容（optional）。

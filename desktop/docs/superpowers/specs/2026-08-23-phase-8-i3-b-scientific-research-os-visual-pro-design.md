# Phase 8-I3-B Scientific Research OS Visual Pro 设计规格

**日期：** 2026-08-23

**状态：** 已批准

**范围：** 仅 `desktop/**` 视觉与交互层

**基线：** Phase 8-I3-A 已完成，现有 `View → Pinia Store → Service Adapter` 数据流保持不变

## 1. 目标

将当前偏“科研管理后台”的 Electron 界面升级为定制级 AI 科研桌面应用。产品应同时具备科学严谨感、现代智能感和长时间工作的舒适度，在 1440×900 与 1920×1080 两种桌面尺寸下保持清晰、稳定、无横向溢出。

本阶段只改变信息呈现、交互反馈、视觉层级与桌面布局，不改变 ResearchAgent、知识层、工具运行时、模型提供方、服务接口或后端架构。

## 2. 已批准的核心决策

1. 采用“平衡型科研工作站”信息密度，而非演示型大留白或 IDE 式高密度。
2. 采用共享设计系统优先的渐进升级，不做逐页孤立换肤，也不引入通用大型 UI 框架。
3. 使用定制 SVG 图标，移除导航和核心业务界面的 Emoji 观感。
4. 默认启动页改为 `/research/dashboard`，侧栏加入“科研首页”；旧 `/dashboard` 路由继续保留兼容。
5. Agent 中心采用“思考时间线 + 智能体协作矩阵 + 工具执行轨迹”三层可观察结构。
6. 文献、实验、数据、论文使用不同的专业工作区结构，共享项目上下文和设计语言，但不复制同一种卡片布局。
7. 数据分析采用 ECharts 科学主题封装，真实消费现有状态数据，不使用静态假图替代工作流结果。
8. 所有用户可见文案保持中文。

## 3. 视觉语言

### 3.1 色彩

- 科学蓝：主操作、选中态、信息结构和数据主序列。
- AI 紫：智能体、推理、AI 建议和协作流程。
- 研究绿：成功、在线、可信度、质量良好和完成状态。
- 警示橙：待确认、引用缺口、实验风险和中等质量。
- 错误红：失败、阻断和危险操作。
- 中性工作面：冷白主背景、纯白卡片、灰蓝面板、深海军蓝正文。

颜色必须通过 CSS 自定义属性消费。页面和通用组件不得新增硬编码主题色；图表数据系列从统一图表主题读取。

### 3.2 排版

- 页面标题：22–26px，紧凑字距，强调当前科研任务。
- 分区标题：15–18px，用于工作区和关键面板。
- 卡片标题：13–15px。
- 正文：13–14px，中文行高不低于 1.55。
- 辅助信息：11–12px，不以极低对比度换取“高级感”。
- 数字指标使用等宽数字特性，论文正文区域可采用衬线中文回退字体以强化阅读语境。

### 3.3 空间与形状

- 4px 基础网格，核心间距为 8、12、16、20、24、32px。
- 主要卡片圆角 14–18px；按钮与输入框 9–12px；胶囊状态使用全圆角。
- 侧栏展开宽度 232px，收起宽度 76px；顶部栏 64px。
- 阴影分为柔和、悬浮、焦点三档。常规卡片以边框和轻阴影为主，避免所有元素同时悬浮。

### 3.4 动效

- 快速反馈 140–180ms，页面与面板过渡 220–320ms。
- 页面进入使用轻微透明度与 6–10px 位移；卡片悬停最多上移 2px。
- Agent 运行态使用单点柔和呼吸光，完成与等待状态保持静止。
- 进度变化使用缓动插值，不循环制造虚假活动感。
- `prefers-reduced-motion: reduce` 下关闭位移、呼吸和连续动画，只保留即时状态切换。

## 4. 应用外壳

### 4.1 侧栏

导航顺序：

1. 科研首页
2. 科研助手
3. 项目空间
4. 文献研究
5. 实验设计
6. 数据分析
7. 论文生成
8. 知识图谱
9. Agent 中心
10. 系统设置

侧栏包括产品标识、分组标题、当前研究摘要和收起控制。当前研究摘要展示项目名与进度。展开状态保存到本地存储，不进入业务 Store。收起后保留图标、工具提示和可辨识的选中态。

### 4.2 顶部栏

顶部栏展示当前层级或页面标题、当前项目、AI 在线状态、通知入口和用户区域。退出操作收进用户区域，不作为常驻高强调按钮。通知和用户按钮具备键盘焦点、可读标签和明确悬停状态。

### 4.3 内容区

内容区使用自适应容器：1440px 视口采用 20–24px 页边距；1920px 视口采用 28–32px 页边距并扩大网格间距。三栏工作区优先保证中间主任务区域，不按比例盲目放大侧栏。

## 5. 页面设计

### 5.1 科研首页

- 项目 Hero：项目名称、研究方向、更新时间、协作者、研究进度和 AI 当前任务。
- 科研指标：文献、实验、数据集和论文状态，展示趋势或质量而非只显示数量。
- AI 活动时间线：显示时间、动作、执行智能体和证据状态。
- 研究洞察：区分 AI 发现、关键结论和推荐方向，并呈现证据数量或置信信息。

### 5.2 Agent 中心

- 左侧思考时间线：理解问题、检索知识、分析机制、设计实验、生成报告。
- 节点状态：完成、运行、等待、错误，颜色与图标双重表达。
- 智能体协作矩阵：规划、知识、实验、分析、写作智能体；显示任务、状态和耗时。
- 工具执行面板：工具名称、本地或远程来源、输入摘要、输出摘要、执行耗时和逐步轨迹。
- 错误态保留已完成轨迹，明确失败步骤和重试入口，不清空上下文。

### 5.3 文献研究

- 论文卡展示题名、作者、年份、相关度、证据等级和引用位置。
- 悬停只展开次级元数据；完整 AI 摘要在稳定侧面板展示，避免卡片高度跳动。
- 引用弹层提供页码、图表或段落定位，并支持键盘关闭。
- 空状态引导导入或检索文献；加载状态使用论文骨架结构。

### 5.4 实验设计

- 三栏布局：研究假设、变量与分组、AI 建议。
- 参数使用可编辑字段与单位，AI 建议使用独立紫色语义标签。
- 假设、变量、分组和指标保持清晰边界；保存中、已保存和保存失败均有反馈。
- 1440px 下三栏不得横向溢出，必要时压缩左右辅助栏而不压缩核心变量编辑区。

### 5.5 数据分析

- 使用 ECharts 封装科学图表主题，支持平滑曲线、拟合线、置信区间、优化图例和响应式重绘。
- 模型拟合卡展示模型名称、R²、置信信息、质量标签和中文 AI 解释。
- 图表组件处理空数据、非法数据、窗口缩放和卸载释放。
- 图表颜色、字体、网格线、提示框和图例统一消费设计令牌。

### 5.6 论文生成

- 三栏布局：论文结构树、正文草稿、SCI 审阅。
- 审阅维度包括语言、逻辑、创新和引用；每项同时显示结论与可执行建议。
- 正文区域强调长文本阅读，不使用过多卡片分割连续文章。
- 选中文本、建议定位和引用缺口有清晰但克制的标记。

### 5.7 项目空间

- 作为跨模块中央工作区，顶部固定项目名、研究方向、AI 状态和进度。
- 标签包括项目概览、文献、实验、数据、模型、论文。
- 切换标签不重建业务状态；现有 Store 继续作为单一数据来源。

### 5.8 知识图谱与系统设置

- 知识图谱沿用科学蓝、AI 紫和研究绿的实体语义，控制面板与画布层级明确。
- 设置页采用左侧分组导航与右侧表单，不改变模型提供方和服务接口。
- 危险操作必须与普通保存操作在颜色、位置和确认反馈上区分。

## 6. 组件与文件边界

计划建立以下职责清晰的单元：

- `styles/research-design-tokens.css`：颜色、排版、间距、圆角、阴影、层级和断点。
- `styles/research-global.css`：全局工作面、滚动条、焦点、选中文本和基础排版。
- `styles/research-motion.css`：页面、卡片、进度和 Agent 状态动效及减少动态效果规则。
- `components/icons/ResearchIcon.vue`：类型安全的定制 SVG 图标入口。
- `components/research/ResearchPageShell.vue`：统一页面标题、说明、操作区和内容容器。
- `components/research/ResearchPanel.vue`：面板标题、状态、操作和内容区。
- `components/research/ResearchState.vue`：加载、空、错误三态。
- `components/research/ScientificChart.vue`：ECharts 初始化、更新、缩放和释放。
- 现有 `Card`、`Button`、`Loading`、`EmptyState`、`ErrorState` 与科研组件继续保留公开接口，内部迁移到新令牌。

文件的准确增删清单和任务顺序在实现计划中确定。不得为了视觉升级重构现有 Store 或 Service Adapter。

## 7. 数据流与状态

数据流保持：

```text
科研页面 → 现有 Pinia Store → 现有 Service Adapter
     ↓
纯展示组件（props）→ 用户操作（emit）→ 页面动作
```

- 通用展示组件不导入 Pinia Store 或 Service Adapter。
- 页面继续调用现有 Store Action，视觉组件只呈现已存在的数据和状态。
- 不新增后端字段，不伪造业务返回值，不修改 IPC 或服务接口。
- 示例内容只可作为无数据时的视觉预览或测试 fixture，不得覆盖真实数据。

## 8. 全局反馈与错误处理

统一反馈文案：

- 加载：`AI 正在分析...`
- 空状态：`暂无科研数据`
- 错误：`分析失败，请重试`

每种状态同时包含图标、标题、辅助说明和适用操作。加载状态避免布局跳动；空状态给出下一步；错误状态保留已有内容并提供重试。禁用态不能只靠降低透明度表达。

## 9. 可访问性

- 交互元素具备可见焦点和中文可读标签。
- 图标按钮提供 `aria-label`；状态不只通过颜色表达。
- 正文与背景、辅助文字与背景达到桌面应用可读对比度。
- 弹层支持 Escape 关闭并恢复触发元素焦点。
- 图表提供中文标题、文字摘要和非颜色区分的系列图例。
- 键盘导航顺序与视觉顺序一致。

## 10. 测试策略

新增不少于 300 个有效测试实例，使用 Vitest、Vue Test Utils 和浏览器模拟环境。测试矩阵包括：

- 设计令牌完整性、语义映射和硬编码主题色隔离。
- 图标名称、SVG 输出、可访问标签和未知名称降级。
- 侧栏导航、当前路由、收起状态、默认科研首页和旧路由兼容。
- 页面和通用组件真实挂载、中文标签、交互事件和键盘行为。
- 加载、空、错误、禁用、完成、运行、等待和异常状态。
- Agent 时间线、智能体卡片和工具执行结果的状态映射。
- ECharts 初始化、数据更新、尺寸变化、空数据和卸载释放。
- 1440×900 与 1920×1080 断点契约、无横向溢出规则。
- `prefers-reduced-motion` 降级与页面过渡类。
- 页面只能连接既有 Store/Service，通用展示组件不得越过隔离边界。

测试数量不得通过重复无意义断言凑数；表驱动测试的每个实例必须验证不同的标签、状态、组件或令牌契约。

## 11. 验证与完成条件

必须执行并通过：

```text
npm run test:unit
tsc --noEmit -p tsconfig.node.json
vue-tsc --noEmit -p tsconfig.web.json
npm run build
```

还必须验证：

- `git diff -- web app backend` 输出 0 行。
- 所有变更位于 `desktop/**`。
- 新增测试不少于 300 个，且现有测试无回归。
- 1440×900 与 1920×1080 下无横向溢出、裁切或不可读文字。
- 页面真实状态、空状态、加载状态和错误状态均完成视觉检查。
- Agent 运行、完成、等待和错误节点的表现可辨识。
- 构建产物成功生成，控制台无新增错误。

## 12. 非目标

- 不修改 `web/`、`app/`、`backend/`。
- 不修改 ResearchAgent、知识层、工具运行时、模型提供方或服务接口。
- 不新增后端 API、数据库字段或业务状态。
- 不为移动端重新设计独立信息架构。
- 不引入与本阶段无关的主题切换、国际化或业务功能。

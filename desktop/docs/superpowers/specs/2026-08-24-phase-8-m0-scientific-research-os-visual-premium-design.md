# Phase 8-M0 Scientific Research OS Visual Premium Upgrade 设计规格

**日期：** 2026-08-24

**状态：** 已批准视觉方向，待规格复核

**范围：** 仅 `desktop/**`

**基线：** Phase 8-I3-B、8-K0～8-K3、8-L0 已完成；现有路由、Pinia Store、Service、IPC 与科学数据模型保持兼容

## 1. 目标与产品定位

将现有 Scientific Research OS 升级为专业 AI 科研桌面工作站。产品既要支持文献、论文和研究规划等长时间阅读与编辑，也要支持设备、实验闭环和预测等高密度实时监控。

设计基调融合：

- Cursor、Linear 的克制层级、快速导航和状态反馈；
- Notion 的长文阅读、连续编辑和知识组织；
- OriginPro 的科学图表、指标单位和分析语义；
- LabVIEW 的实时状态、设备拓扑、安全联锁和仪器感。

所有用户可见文案使用中文；学术术语、单位、论文题名、变量名和行业惯用缩写可保留英文。

## 2. 已批准的核心视觉决策

1. 采用“浅色科研工作台＋深色 SCADA 控制台”的混合模式。
2. 暖珊瑚色保留为关键行动、AI 洞察和待确认状态的强调色，不作为大面积背景。
3. 浅色工作区使用雾白、石墨灰和深青，服务文献阅读、数据分析、知识组织和论文写作。
4. 实验控制中心使用固定深色仪器主题，突出实时曲线、设备运行、联锁和预测风险。
5. 两种工作面共享同一套排版、间距、圆角、状态、焦点和动效语法，不形成两套割裂产品。
6. 视觉升级复用现有真实 Store/Service 数据；演示 fixture 只用于测试，不进入产品运行路径。
7. 页面结构按科研任务定制，不将所有页面统一成相同卡片墙。
8. 1440×900 是主要密度基线，1920×1080 扩展信息宽度但不盲目放大控件。

## 3. 设计系统

### 3.1 色彩语义

浅色科研工作台：

- `graphite-950`：主正文、主按钮和强结构；
- `mist-50`：应用背景；
- `paper-0`：卡片、编辑器和浮层；
- `teal-700`：可信、在线、科学主序列和选中态；
- `coral-500`：AI 洞察、关键行动、待确认和重要定位；
- `amber-500`：维护提示、风险预警和中等置信；
- `red-600`：故障、越限、阻断和危险操作。

深色 SCADA：

- `instrument-950`：控制台背景；
- `instrument-900/850`：分区与设备卡；
- `instrument-line`：网格、分隔和非活动结构；
- `signal-green`：运行、实时数据和安全状态；
- `signal-amber`：预测窗口、警戒和人工确认；
- `signal-red`：报警、联锁触发和危险；
- `signal-cyan`：辅助过程变量与选择反馈。

规则：

- 所有主题色通过 `research-design-tokens.css` 暴露；页面不得新增散落的主题硬编码。
- 状态同时通过颜色、图标、文字或形状表达。
- 图表序列色与状态色分离，避免“某条普通曲线看起来像报警”。
- 大面积底色保持低饱和，颜色集中在数据、状态和决策点。

### 3.2 排版

- UI 字体：Inter、PingFang SC、Microsoft YaHei 的系统回退链。
- 数字、时间、设备编号、变量和单位启用等宽数字特性。
- 论文正文优先使用适合长文阅读的衬线回退链，编辑工具栏仍使用 UI 字体。
- 页面标题 24px；分区标题 16～18px；卡片标题 14～15px；正文 13～14px；辅助信息 11～12px。
- 中文正文行高不低于 1.55；论文正文行高不低于 1.72。
- 不使用全大写中文；英文微标签只用于产品标识、设备编号和科学变量。

### 3.3 空间、形状和层级

- 基础网格 4px；主间距序列为 4、8、12、16、20、24、32、40px。
- 普通控件高度 32～36px；核心操作 36～40px；紧凑 SCADA 控件不低于 30px。
- 卡片圆角 12～14px；输入和按钮 8～10px；大工作面 16～18px；状态胶囊全圆角。
- 常规层级以边框、背景差和轻阴影建立；浮层、聚焦面板和拖拽态使用更高阴影。
- 不嵌套多层卡片。工作区通过分栏、分隔线和留白组织，卡片只承载独立信息单元。

### 3.4 动效

- 快速反馈 140～180ms；面板与路由过渡 220～300ms；数据插值 300～500ms。
- 页面进入只使用轻微透明度与 4～8px 位移。
- 设备运行态允许单点呼吸和管路流动；禁止大面积循环闪烁。
- 实时图表追加数据使用平滑位移，不整图淡入重绘。
- `prefers-reduced-motion: reduce` 下关闭位移、呼吸、旋转和连续流动，只保留即时状态更新。

### 3.5 统一状态模型

通用状态：默认、悬停、聚焦、选中、禁用、加载、空、成功、警告、错误。

科研运行状态：待机、准备、运行、暂停、完成、失败、离线、维护。

AI 状态：等待、规划、检索、执行工具、分析、写作、审阅、需要确认、失败。

所有状态具备中文可读标签；加载不引发布局跳动；错误保留已成功内容和可重试入口。

## 4. 应用外壳与全局导航

### 4.1 桌面外壳

- 顶部栏展示产品标识、当前项目、系统在线状态、全局搜索、通知和用户入口。
- 当前项目选择器是全局上下文，不在每页重复大块项目卡。
- 侧栏展开时展示分组和中文名称，收起时保留图标、工具提示和明确选中态。
- 主内容区使用页面级滚动；固定工具栏仅用于持续编辑或控制场景。

### 4.2 导航顺序

1. 科研驾驶舱
2. 科研助手
3. 研究工作区
4. 文献研究
5. 实验设计
6. 数据分析
7. SCI 写作
8. 知识图谱
9. AI 研究团队
10. 实验控制中心
11. 系统设置

旧有可达路由保持兼容；导航名称升级不改变路由契约。

### 4.3 全局反馈

- Toast 用于短期结果，不用于承载需要用户阅读的错误详情。
- 长任务在页面内显示阶段、执行者、证据和剩余信息，不只显示无限旋转图标。
- 全局命令或搜索遵循 Escape 关闭、焦点恢复和键盘导航规则。
- 离线、设备断连或 AI 服务不可用时，在上下文附近展示影响范围。

## 5. 页面设计

### 5.1 科研驾驶舱 Dashboard

目标是“科学驾驶舱”，回答现在在研究什么、进展怎样、AI 在做什么、实验是否安全、最近发现了什么。

结构：

- 当前研究焦点：项目、阶段、目标、AI 当前任务和总体进度；
- 科研指标：本周实验、AI 活动、证据覆盖、设备健康；
- AI 活动：Agent、动作、证据状态、耗时和结果入口；
- 实验状态：当前 Run、运行时间、核心过程变量和闭环状态；
- 设备健康：反应器、泵、臭氧发生器、传感器阵列及维护提示；
- 近期洞察：结论、证据数量、置信度、关联实验或文献和确认状态。

指标卡必须提供趋势、上下文或质量信息，不只陈列数字。

### 5.2 科研助手 Assistant

- 对话区是核心，不以侧栏卡片挤压阅读宽度。
- 顶部展示当前研究项目、模型和科研模式。
- AI 回复区分结论、证据、推理摘要、引用和后续行动。
- 工具运行折叠区展示 Agent、工具名、阶段、耗时、输入摘要与输出摘要。
- 输入区支持研究对象上下文、附件、停止生成和重试状态。

### 5.3 文献研究 Literature

- 左侧为检索、筛选和文献集合；中间为结果列表；右侧为稳定阅读与 AI 证据面板。
- 文献项展示标题、作者、年份、期刊、相关度、证据等级和引用状态。
- AI 摘要、关键结论、方法与局限在右侧展示，避免列表项高度跳动。
- 引用必须支持页码、章节或图表定位；无定位时明确标记“待核验”。

### 5.4 实验设计 Experiment

- 假设、变量、实验组、设备约束和评价指标形成清晰顺序。
- AI 建议与人工设定使用不同语义，接受建议必须是显式操作。
- 参数值与单位不可分离；范围、步长和安全边界可快速扫描。
- 保存中、已保存、验证失败、冲突和设备不可用均有局部反馈。

### 5.5 数据分析 Data Analysis

- 顶部为数据集、分析方法和质量摘要；中部为主图；下部为模型与解释。
- 科学图表支持单位、置信区间、拟合线、异常点、图例切换、缩放和响应式重绘。
- 模型卡显示算法、R²/误差、验证方法、数据量、可信度和中文解释。
- 不用仪表盘装饰替代实际图形；空数据和非法数据有明确降级。

### 5.6 SCI 写作 Manuscript

采用三栏连续写作环境：

- 左侧：论文结构、章节状态、字数和引用数量；
- 中间：纸张式正文编辑器、上下文工具栏、选区和引用标记；
- 右侧：Reviewer Agent 的语言、逻辑、创新、证据和引用意见。

意见必须能定位到文本，并提供“定位证据”“生成改写”“插入引用”等可执行入口。正文保持连续阅读，不将每段拆成卡片。

### 5.7 知识图谱 Knowledge Graph

- 图谱画布为主，搜索、图例、过滤和布局控制保持紧凑。
- 实体类型使用稳定颜色和形状映射；选中节点在侧面板展示来源、关系、证据和关联项目。
- 推理路径和普通关系在视觉上可区分；降低动态效果时停止持续布局动画。
- 空图、超大图、布局失败和证据缺失均有可恢复状态。

### 5.8 AI 研究团队 Agent Center

展示五个明确角色：

- 文献 Agent：检索、筛选、证据提取和引用核验；
- 实验 Agent：假设转实验、参数建议和约束校验；
- 分析 Agent：数据质量、统计建模、异常与解释；
- 写作 Agent：章节生成、术语统一和引用编排；
- 审稿 Agent：语言、逻辑、创新性和证据审查。

界面由团队概览、协作时间线、任务队列和工具轨迹组成。运行、等待、需要确认、完成和失败状态必须在不依赖颜色时仍可辨识。失败保留上游成果与错误步骤。

### 5.9 研究工作区 Research Workspace

- 作为跨模块研究中枢，固定呈现项目目标、阶段、进度、风险和 AI 当前行动。
- 工作区标签覆盖概览、文献、实验、数据、模型、论文和事件。
- 标签切换不重置 Store；跨模块条目支持返回来源上下文。
- 研究进度由既有工作流事件派生，不在 UI 维护第二份业务状态。

### 5.10 实验控制中心 Experiment Control Center

升级为专业科学 SCADA：

- 固定深色控制台，顶部展示实验、Run、实时延迟、安全联锁和人工接管状态；
- 实时趋势展示过程变量、单位、阈值、设定值、预测区间和时间轴；
- 设备卡展示状态、关键读数、设定值、通信延迟、健康和维护；
- 预测面板展示未来窗口、置信区间、越限风险、最佳采样窗口和建议依据；
- 报警区按严重度、时间、设备、确认状态组织；危险操作需要明确确认。

不得通过纯装饰动画制造“实时”假象。实时状态来自既有 experiment control Store 和服务。

### 5.11 系统设置 Settings

- 左侧分组，右侧表单；模型、设备、通知、外观和隐私的边界清楚。
- 保存状态靠近当前分组；失败不丢失用户输入。
- 危险操作与普通设置在位置、颜色、文案和确认流程上明确分隔。

## 6. 数字孪生设备可视化

数字孪生面板支持四类设备：

- 反应器：液位、温度、压力、pH、内部状态和设定值；
- 循环泵：频率、流量、振动、运行方向、健康和维护预测；
- 臭氧发生器：浓度、功率、输出、联锁和运行效率；
- 传感器：测量值、单位、采样时间、质量标记、漂移和通信状态。

视觉结构：

- 设备拓扑使用轻量 SVG/CSS 图形或现有可维护组件，不引入大型 3D 引擎。
- 管路用方向和流动状态表达介质关系；减少动态效果时改为静态箭头。
- 设备选中后展示详情，悬停只显示简短读数，避免遮挡主拓扑。
- 状态与读数来自现有数字孪生、设备和控制中心数据模型。
- 缺测、延迟、离线和模拟数据必须明确标识，不可伪装成实测值。

## 7. 组件架构与文件边界

优先建立共享原语，再升级页面：

- `styles/research-design-tokens.css`：浅色、SCADA、排版、间距、圆角、阴影、层级和断点；
- `styles/research-global.css`：应用工作面、排版、滚动条、焦点和选区；
- `styles/research-motion.css`：页面、Agent、设备、图表状态和 reduced-motion；
- 现有科研 Shell/Panel/State 组件：统一标题、操作、状态和内容边界；
- 科学图表组件：主题、ResizeObserver、空数据、更新和卸载；
- 数字孪生设备组件：反应器、泵、臭氧发生器和传感器；
- Agent 团队组件：角色卡、协作轨迹、任务状态和工具执行；
- SCI 写作组件：结构树、正文工作面、审稿意见和引用定位。

准确文件清单由实现计划在代码审计后确定。禁止为视觉升级重构 Store、Service、IPC、共享科学 Schema 或 Electron 主进程业务。

## 8. 数据流与错误边界

```text
页面 → 现有 Pinia Store → 现有 Service / IPC
  ↓
展示组件（props）← 页面适配后的 view model
  ↓ emit
页面 action → 现有 Store action
```

- 通用展示组件不直接导入 Pinia Store 或 Service。
- 页面继续作为业务状态和视觉组件的适配边界。
- 图表与数字孪生组件接受显式数据、状态、单位和时间戳。
- 不新增后端字段，不修改 `backend/`、`web/`、`app/`。
- 错误状态保留最近一次有效数据，并清楚标注数据时间与错误影响。

## 9. 响应式设计

### 9.1 1440×900

- 以紧凑专业密度展示，页面边距 20～24px。
- 驾驶舱采用 8/4 或 7/5 主辅网格；指标卡可四列。
- SCI 写作和实验设计保持三栏，优先保障中间核心区域。
- SCADA 数字孪生与预测面板并排，趋势图占完整宽度。
- 不出现页面级横向滚动；数据表自身可局部滚动。

### 9.2 1920×1080

- 页面边距扩大至 28～32px，内容最大宽度控制在适合阅读和扫视的范围。
- 驾驶舱可扩大时间线、洞察和设备区，不放大按钮与字号。
- SCADA 利用额外宽度展示更长时间窗、设备详情和预测信息。
- SCI 正文维持舒适行宽，将额外空间分配给结构树和审稿面板。

### 9.3 边界规则

- 最低支持宽度按桌面 1180px 设计；更窄时允许辅助栏折叠，不改变信息优先级。
- 所有图表监听容器尺寸，不使用固定视口宽度计算。
- 固定定位元素不得遮挡主要操作、Toast、弹层或滚动内容。

## 10. 可访问性

- 所有交互元素具备可见 `:focus-visible`，键盘顺序与视觉顺序一致。
- 图标按钮提供中文 `aria-label`；当前路由使用 `aria-current`。
- 标签、输入、单位和错误信息具备程序化关联。
- 图表提供中文名称、文字摘要和不依赖颜色的图例。
- 动态更新使用适度的 live region，不播报每个采样点。
- 弹层支持 Escape、焦点限制和关闭后焦点恢复。
- 主题对比度满足长时间桌面阅读；禁用态不只依赖低透明度。
- reduced-motion 下保持全部信息与操作能力。

## 11. ≥300 条 UI 视觉契约测试

测试使用 Vitest、Vue Test Utils 和 happy-dom，采用可读的表驱动契约。每个测试实例必须验证不同标签、状态、路由、组件、令牌、响应式或可访问性行为，禁止复制断言凑数。

最低测试分配：

| 契约域 | 最低实例数 |
| --- | ---: |
| 中文页面、导航与关键标签 | 55 |
| 共享组件结构、props、事件和状态 | 70 |
| 路由、选中态、旧路由兼容和页面挂载 | 35 |
| 可访问名称、焦点、语义角色和键盘行为 | 50 |
| 动效类、运行状态和 reduced-motion | 30 |
| 设计令牌、主题与 SCADA 语义 | 30 |
| 1440×900、1920×1080 与无溢出契约 | 20 |
| 图表、数字孪生、空/错/加载和卸载 | 30 |
| **总计** | **320** |

契约统计必须由测试代码生成或由清晰的 case 数组汇总，测试输出可验证实际数量不少于 300。

重点验证：

- 11 个页面的中文标题、核心模块和可达路由；
- 五类 Agent 的名称、职责、状态和工具轨迹；
- 反应器、泵、臭氧发生器、传感器及离线/故障/模拟状态；

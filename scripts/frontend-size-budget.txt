# 前端复杂度热点体量棘轮基线 (wc -l 口径)
#
# 消费方: scripts/frontend-size-budget-check.sh  ← .github/workflows/lint-css.yml
#        job frontend-unit-tests 的 "Frontend size budget (ratchet)" 步
#
# 格式: kind|path|limit[|note]
#   kind=file  单文件上限，文件不存在即门禁失效 (fail)
#   kind=glob  目录下 *.js **递归** 合计上限，目录为空/不存在则跳过
#   note       可选，仅支持字面量 provisional（暂定基线，见下）
#
# ⚠️ 覆盖边界 —— 本门禁只覆盖下列 5 个条目，不做全仓扫描。
#   新增大文件**不会**被自动纳入，必须手工加一行才有约束。
#   已知未覆盖: web/src/utils/ 顶层共 16 个 .js，本基线只点名了其中 1 个
#   (paperAdapter.js)；web/src/**/*.test.js 亦不在本基线内（见末尾取舍说明）。
#   棘轮只盯热点是对的，但它**必须写明自己不知道什么**，否则下一个人会误以为
#   新大文件自动被管住 —— 这与 S3.7 ⑧ "新文件失明" 是同一型错误。
#
# ⚠️ 2026-10-02 (S3.8 前置): 新增 glob 一类。
#   原实现是 declare -A 硬编码三条, 对 paperAdapter.js 拆分产生的新文件
#   (web/src/utils/paper/*.js) 完全失明 —— "只降不升"的保护在拆分当天即失效。
#   glob 基线 5500 —— 依据是 2026-10-02 实测的按函数边界切分合计 **5348**
#     (qa 125 / content 684 / sections 1042 / figures 1369 / normalize 2128,
#      L286-5633 零缝隙零重叠), 外加每文件 ~16 行 boilerplate 余量。
#   前一版写的 "3700（勘察估算 ~3600）" 低估 1648 行 —— 该估算把"拆分"
#     当成了带删减的拆分, 实测是**零删减搬家**: 真死码仅 24 行
#     (_embedAnchors 7 行 + _isTocPage 17 行), 注释 1679 + 空行 429 占 37.4%。
#     按 3600 卡, 第一次拆分 PR 必然被自己的棘轮拦下, 而"放宽基线"正是
#     S3.7 ⑧ 刚出过事的那一面。
#   取 5500 而非 5348: 零余量意味着拆分方只要多写 100 行注释就红灯,
#     实际会诱发"改基线"而不是"真减重"。152 行余量足够吸收正常增补。
#   **真减重压力由 paperAdapter.js 那条 5633 承担** —— 它才是主体;
#     glob 这条是防双计/脱管的护栏, 不是减重指标。
#   首次拆分 PR 完成后, 必须用 wc -l 实测合计替换 5500, 并把 note 段清空。
#     脚本会在每次运行时 ::notice 提醒此事（含目录尚未建立的跳过路径）。
#
# 纪律: PowerShell 下数行数必须显式 -Encoding UTF8 (或用 pwsh 7+)。
#   本文件无 BOM, 按 ANSI 代码页解码会吞掉换行 (5633 -> 5011), 再叠加
#   Measure-Object -Line 跳空行 -> 4588。详见 docs 2026-09-30-phase-closeout-plan.md
#   "工具可信度判据" 段。**行数一律以 wc -l 为准。**

# ⚠️ 2026-10-02 (E2 决策): S3.8 拆分**不留 barrel**。
#   留 barrel 的后果: paperAdapter.js 变成 60 行的壳, 仍被计入 file 条目,
#   而 paper/ 五文件被 glob 计入 —— **同一批代码算两遍**, 合计从 5633 变成约 10400。
#   合计完全失真(看起来像翻倍恶化, 实际是搬家), 且 API 面没收窄、体量没下降。
#   故 S3.8 采"真拆": 删除 paperAdapter.js, 改 8 处 import 直接指向 paper/*。

#   交付判据: `sh scripts/frontend-size-budget-check.sh` 本地 exit 0,

## 四、关键技术事实（新 agent 必读，历代踩坑换来的）

**本机环境陷阱**：
- `AppData\Local` 实际在 **D 盘**（`D:\Users\pc\AppData\Local`），C 盘同名是空壳；安装版在 `D:\Users\pc\AppData\Local\Programs\MicroBubbleWorkbench`
- 沙箱间歇 EPERM → 本地 vitest 计数会波动，跑到的全过即可提交，**全绿结论以 CI 为准**（现在仓库 Public，CI 无额度顾虑，一轮仅 ~4-5 分钟）
- `node -e` 内嵌探测静默失败——探测一律用**临时脚本文件**；凡「子进程探测+按退出码判定」的脚本，catch 路径必须 `process.exit(1)`
- 改仓库文件用 **Edit 工具**（Python replace 曾静默失效）；提交链用 `&&` 串联（曾两次绕过门禁）
- 父仓有 **post-commit 自动 push 钩子**（commit 即推 origin）；GitHub 22 端口间歇阻断 → 一次性 `GIT_SSH_COMMAND="ssh -o Hostname=ssh.github.com -o Port=443" git push`
- 杀应用进程用 `taskkill //F //IM`（powershell 被沙箱禁用）；改用 dangerouslyDisableSandbox 谨慎
- **并行会话风险**：用户会开多 agent 并行。重写历史/大规模操作前确认无在途工单；执行端 gate 过了立即 commit

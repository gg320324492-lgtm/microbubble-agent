# M8「Agent 能力升级」计划（对标 minimax-code）

> 2026-09-19 · 总指挥出计划。依据：决策 D9（采纳 MiniMax 开源项目 minimax-code 对标提升点）。
> 对标仓库：github.com/MiniMax-AI/minimax-code 0.4.12（MIT；分析全文见执行 agent 会话与本文 §2 摘要）。

## 0. 背景与结论

MiniMax Code 是终端编码 agent，双层结构：vendored pi-mono 底座（MIT，极简纯函数 agent 循环与事件流）+ MiniMax 自研编排层（重试自愈/compaction/三级权限/runaway guard/goal 验证闭环）。对照我们的科研 agent（六模块 + ReAct 全链路已落位），差距点高度重合且价值密度高。**借鉴模式（思想/架构）无协议风险；如需逐字复制代码：pi-mono 部分保留 MIT 归属、sandbox-runtime 部分保留 Apache-2.0 声明。**

## 2. 分期落位

- **M8-1（P0 硬化，体量小-中）**：#1 工具输出预算+续读协议、#2 提交边界重试+错误归一化、#5 循环与 SSE 解耦（测试基建）——三件事相互配套，一次落位
- **M8-2（上下文管理，中）**：#3 第一步（估算器+触发线+保留近端+原子裁切）；#3 第二步（LLM 摘要+持久化替换）与 #11 成本记账随车
- **M8-3（权限与体验，中）**：#4 三值权限+梯度+证据链；随车小件 #6 #7 #8 #9 #10
- **P2 池**（v1.0 后按需评估）：#12 #13 #14 #15
- 排期建议：M6-2（进行中）→ **M8-1 → M8-2 → M8-3 → M7 UI 换新 → v1.0**（Agent 硬化先于 UI 换新——UI 是面子，Agent 稳定性是里子；且 M8 各单体量小于 M7）

## 三、这份文档讲了什么（三句话版）

1. **产品定位**：不要做"更像 Codex 的聊天窗口"，要做"科研工作台"——
   **聊天只是入口，项目是载体，任务是核心，成果文件是最终交付物**（§1.1）。
2. **差异化五点**（§1.3）：科研任务模板化、项目上下文长期化、成果文件化、证据可追溯、
   科研可复现（图表对应代码、统计对应数据、结论对应证据）。
3. **落地路径**：§19.4 给了非常具体的开发顺序——先做「项目」数据结构 → 把已有对话 Agent
   嵌进项目 → 统一 Task 对象 → **只做第一个任务模板：Excel → 绘图 → 导出图和代码** →
   第二个做 PDF → 文献矩阵 → 第三个做带引用证据的论文段落。
   §20.12 语音的顺序同理：**语音不另造业务逻辑，复用已有任务系统和工具权限**。

MVP 分级：P0 六项（项目工作区 / 文献解析 / Excel 分析 / 科研绘图 / 成果包 / 任务中心）、
P1 七项（写作编辑器、文献矩阵、SOP、组会周报、项目记忆、多模型路由、实时语音 Beta）、
P2 六项（多人协作、共享知识库、仪器适配、Zotero/Overleaf/Git 集成、私有部署、自动化工作流）。

## 五、必须你先拍板的 5 个决策点（**我不预设答案，等指令**）

**① 路线图 §7/§8 与 DL-6 的裁决冲突——最硬的一处**
DL-6 是你 2026-09-29 的产品裁决「不需要了」，把「实验 ELN」「稿件」两模块下架。
路线图 §7 写作编辑器 + §8 电子实验记录/SOP 正是这两块。
→ 选一：**(a)** 推翻 DL-6 恢复（那 v1.3.1 的下架白做）；**(b)** 维持下架，路线图这两章整章不做，
其余章节照走；**(c)** 只借 §7 的「证据驱动」理念，不做写作器。
**不定这条，§7/§8 不能进任何工单。**

**② Project Space 与现有「网盘 + 知识库」是合并还是并存**
路线图把"项目"当作最上层对象、文件树挂在项目下；本仓是五项平铺侧栏。
→ 合进网盘/知识库（省一套数据模型）／独立新增项目层（概念更干净但多一套真相源风险）。

**③ 本地优先 vs 服务器优先（§12.4 与现状相反）**
现状数据住 `agent.mnb-lab.cn`。路线图主张"文件索引、项目管理、基础处理尽量本地执行"。
→ 维持服务器优先（改动小）／真做本地优先（要重新设计同步，本仓已有 sync engine 设计文档可参考
`docs/plans/2026-09-18-sync-engine-design.md`）。

**④ 第一任务模板选哪个**
路线图 §19.4 建议「Excel → 绘图 → 导出图和代码」，理由是 3–5 分钟 vs 30–60 分钟价值最直观。
但本仓用户是课题组（微纳米气泡方向），且绘图在本仓是零基础。
→ 照路线图走绘图／换成文献综述（与知识库底座接得上）／你来指定。

**⑤ 实时语音（§20）现在排第几**
§20.12 明确"语音不另造业务逻辑，复用已有任务系统"——**前提是先有任务系统**。
而任务系统（§11）本仓零记载。所以路线图自己的顺序是：任务系统 → 语音，语音是 V0.5 的 Beta。
→ 接受这个顺序（那语音现在只登记不启动）／插队先做语音（则要先补任务系统，否则语音无处发力）。

**另需你确认的一条小事**：路线图 §16 的 `V0.1→V1.0` 版本号与本仓 v1.3.1 冲突。
建议不改本仓版本号，把路线图的 V0.x 当**内部里程碑代号**（如 M-R1/M-R2）使用。

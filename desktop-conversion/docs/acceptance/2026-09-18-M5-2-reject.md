## 打回原因

### 缺陷 1（必须修复）：云端列表 prefix 双拼

`backup.service.ts listRemoteBackups` 传入 `config.prefix`，而 `oss.client.ts listObjects` 内部再次拼接 `config.prefix + prefix` → 实际请求 `prefix=desktop-backup/desktop-backup/`。**真实 OSS 环境下云端列表恒为空**（上传 key 为单前缀，两者错位）——核心功能在真机上不可用。复测 agent 用本地 HTTPS mock 实证了双拼请求。单测未拦截原因：mock 忽略了 prefix 参数。

**修复要求**：统一前缀约定（建议 client 层不再内部拼接，调用方传全量前缀），并补一条 mock 断言用例：listObjects 实际请求的 prefix 参数**精确等于** `desktop-backup/`（锁死双拼回归）。

### 缺陷 2（顺手修复）：endpoint 无 scheme 时 Invalid URL

保存时无 scheme 的 endpoint 进入 `new URL()` 直接抛 Invalid URL。修复：保存时归一化（无 scheme 自动补 `https://`）或给出明确报错文案（二选一，说明理由）。

## 四、非阻塞发现

### 发现 1 · 测试不自包含，缺 env 时连生产库 `[中 · 测试卫生]`

`drive_ingest_tasks.py:48` 的任务体硬编码 `settings.DATABASE_URL`，而测试 fixture 在**测试库**建行。总指挥首跑复现 **6/8**，失败为 `res` 为 `None`（任务在生产库找不到该 id → 404 → `return None`）。补 `DATABASE_URL` 指向测试库后 **8/8 绿**。

- **执行端报告属实**（其运行环境设了该 env），非虚报
- **风险**：任何人漏设该 env，测试会**连生产 `microbubble` 库执行 SELECT**。当前只读未留 debris，但 `tests/conftest.py:34-36` 明写「测试禁止回退 `settings.DATABASE_URL`（生产库）—— 历史上这批测试在生产留 debris」
- **建议**：让任务引擎 URL 可注入（复用 `conftest.get_test_database_url()`），或在测试中 monkeypatch。不阻塞本单。

### 发现 2 · 目录段允许单点 `.` `[低]`

`normalizeBackupSegments` 拒绝 `..` / `\` / 空段，但单点 `.` 会通过并被用于 find-or-create，会建出名为 `.` 的怪文件夹。**非穿越**（按名精确匹配，无拼接），仅建议收紧。

### 发现 3 · `listFolders` 失败时继续 create `[低]`

`ensureRemoteFolderId` 中 `listFolders` 返回 `!ok` 时直接落入 `createFolder`，瞬时网络错误可能被放大成重复建夹。建议 `!ok` 时显式返回失败。**不影响正确性**（保留区按名判定，重复夹仍能工作）。

## 二、非阻塞发现

### 发现 1 · conftest 派生 URL **失败开放** `[中 · 潜在生产事故]`

```python
_settings.DATABASE_URL.replace("/microbubble", "/microbubble_test")
```

- **失效模式**：若生产库改名（如 `mnb_prod`），该 replace 变成**静默 no-op** → 测试 URL == 生产 URL → **测试直接写生产库**。这正是 conftest 铁律要防的事故。
- **次生脆弱**：`.replace()` 是全局替换，密码/主机若含字面量 `/microbubble` 会被改坏（当前密码不含，但脆）。
- **现有缓解**：守卫测试 `test_guard_conftest_test_url_differs_from_production` 会失败告警——**但只在测试跑起来之后**。
- **建议**：改为解析 URL 后**只替换 path 段**，并在模块导入时 `assert` 两者不相等（**导入即失败**，而不是等测试跑完）。另：服务端测试目前**似乎不在 CI 中跑**（已知 CI 是 desktop-release），守卫的实际保护力因此更弱，值得确认。

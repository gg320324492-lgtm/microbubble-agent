## 你的任务背景

用户裁决：**备份对组员必须零操作**——不再有备份密码输入、不再有目录选择、不再有「立即备份」按钮依赖。登录成功的那一刻，应用已知「这个人是谁」（M2-3a+ 云端身份），备份随之全自动生效：

1. 备份目标 = **该用户自己的云端网盘 `backups/` 目录**（复用 M2-3c 已交付的分块上传/列表/删除通道——零服务端改动）
2. 保护密钥 = **自动生成的强随机密码**：本机 safeStorage 保存 + 以 `<容器名>.key.json` 随容器**同目录托管上传**——组员笔记本报废时，负责人可从服务器侧取 key 恢复数据（成员互相隔离：key 在各自网盘目录内，他人经 API 不可见）
3. 每日定时自动执行 + 保留最近 7 份（自动清理最旧）

**与旧交互的关系**：手工「备份密码/目录/立即备份」输入全部退役（对已手工配置的用户——如负责人本人——**保留其既有配置不覆盖**；自动配置仅对「未做过任何备份配置」的用户生效）。

## 交付物

### 1. 自动配置（`src/main/services/backup/auto-provision.ts` 纯函数 + 装配）

- 触发：云端登录成功后（含离线宽容恢复），检测「无任何备份配置」→ 自动生成配置：
  - 备份目标 = 该用户云端网盘 `backups/` 目录（复用 M2-3c 分块上传通道）
  - 保护密钥 = 随机 32 字节 → base64（`crypto.randomBytes`，注入式以便测试）
  - 每日定时 = 开启（默认参数）
- **既有手工配置的用户（如负责人本人）零覆盖**——检测到既有配置即跳过自动配置

### 2. 密钥托管（可恢复性，硬要求）

- 容器上传完成后，`<容器名>.key.json`（含保护密码）**随容器同目录上传**至网盘 `backups/<用户>/`
- 语义：成员互相不可见（各自网盘私有目录）；负责人可服务器侧读取 → **任何组员电脑报废，数据可救**
- 日志与报告**绝不含密码/key 内容**

### 3. 每日自动执行 + 保留策略

- 沿 R-9 定时骨架：每日自动执行（错过不补跑）；保留最近 7 份，超出自动删最旧（复用既有保留逻辑，删的必须是本应用命名模式的文件）

### 4. 离线宽容

- 断网时不执行（顺延到次日）；联网恢复后登录态下正常执行

### 5. UI（最小改动）

- 备份页状态行升级：「已自动保护 · 上次备份 … · 下次 … ｜ 已保留 n/7 份」；手工输入区对未配置用户**隐藏**（自动配置后无需手填）；「高级选项」保留可改

### 6. 测试（≥14，全部离线，注入式）

- 自动配置：未配置→自动生成（密码强度/目标/定时）/ 既有配置→零覆盖 ≥3

- 离线：断网顺延不报错 / 恢复后正常 ≥2

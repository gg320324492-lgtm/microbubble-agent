# 工单 V1：v1.0.0 正式版收官（smoke 主题断言 + 用量记账 + 首个正式版发布）

> 签发：总指挥 · 2026-09-19
> 上游：M7 已验收关闭（v0.1.6-alpha 上线）；测试基线 **330** 条全绿
> 决策依据：D10（v1.0 收官裁决——用户拍板）
> **里程碑意义：本单交付即 v1.0.0 正式版——脱离 alpha 的第一个稳定版本**

## 你的任务背景

应用功能面已完整（六大 IA + 桌面集成 + 备份恢复 + 自动更新通道），CI/CD 已自动化。本单做三件事收尾：**① smoke 门禁增加主题令牌断言**（堵住「CSS 覆盖静默失效」整类缺陷——M7 的 EP 特异性缺陷若早有此断言会被 CI 直接拦截）；**② 用量记账最小实现**（AI 对话的 token 用量可见）；**③ v1.0.0 正式版发布**（首个脱离 alpha 的稳定版，tag 不可变时代的第一次正式发布）。

技术要点：
- smoke 断言落点：`scripts/smoke-package.mjs` 增加 CSS 产物断言——打包产物内 `--el-color-primary` 必须等于品牌色 `#3e5c76`（读取构建产物 CSS 文本断言，不是运行时）
- 用量来源调研：模型网关（M1-B）SSE 流中 Anthropic `message_delta` 携带 usage（output_tokens）；input tokens 在 `message_start`。执行时先调研网关现状：已捕获则直接归一化使用；未捕获则补解析
- 归一化原则（对标 minimax-code llm-retry）：NaN/负数/缺失一律归零，`usageComplete` 标记可信度
- 迁移 010 允许（会话用量累计列）

## 常设红线（违反任一直接打回）

## 交付物

### 1. smoke 门禁主题断言

- `scripts/smoke-package.mjs` 增加：读取打包产物内 CSS（app.asar 解包或构建产物 CSS 文件），断言 `--el-color-primary: #3e5c76` 存在（品牌色）
- workflow 的 smoke 步骤自动继承（脚本内断言，无需改 workflow 逻辑）

### 2. 用量记账最小实现

- 网关层：SSE 流 usage 捕获归一化（`{inputTokens, outputTokens, cacheReadTokens?}`，NaN/负数/缺失归零）
- 持久化：**迁移 010**——`chat_sessions` 增加用量累计列（如 `tokens_in INTEGER NOT NULL DEFAULT 0 / tokens_out INTEGER NOT NULL DEFAULT 0`），每轮完成累加
- 展示：设置页「关于与更新」区块或对话面板轻量展示会话累计用量（二选一，说明理由）
- 不做：费用换算（模型价格变动频繁，P2）、按消息级展示

### 3. v1.0.0 正式版发布（严格顺序）

1. 版本两处同步 → **`1.0.0`**（脱离 alpha；constants.ts + package.json）
2. CHANGELOG.md 顶部新增 **`v1.0.0（首个正式版）`** 全量总结段落（自 v0.1.0 以来的能力全景：六大模块 / Agent 读写全链路 / 桌面集成 / 备份恢复 / 自动更新 / 宣纸暖白 UI / CI 门禁体系，压缩为用户视角的分节介绍）
3. 门禁全过 → 本地打包 → **test tag `v1.0.0-ci.1` 首航** → CI 全绿 + 产物下载 → **产物可运行性验证（含新增主题断言）**
4. 通过后：推正式 tag **`v1.0.0`** → `gh release create v1.0.0 --title "小气 · 科研工作台 v1.0.0" --notes-file <正文> --verify-tag`（**不加 --prerelease**）→ 上传三件套 → 自验
5. Release 正文：v1.0.0 段落 + 安装说明（含「从 v0.1.x 覆盖安装数据自动延续；应用内『检查更新』可直升 v1.0.0」）

### 4. 发布审计清单（沉淀）

- `docs/` 或仓库内落 `release-audit` 清单模板：版本两处一致 / 门禁 / 产物 sha256 与 Release digest 比对 / 匿名 200 / 可运行性 / 真机抽查项——v1.0 起每次发布逐项打勾

# 缺陷单 DL-1：统一登录与远程数据源状态断层（知识库/网盘显示「未绑定」）

> 签发：总指挥 · 2026-09-21 ｜ 优先级：**高（阻断远程模块全部真机验证）**
> 基线：`49fa15cee` / 689 条（以接单实测为准）

## 症状（用户真机）

- 用户经**统一登录**（父级账号）成功进入主界面（标题栏显示登录名）
- 知识库页却显示引导态：「需连接云端才能使用知识库 / 请到『设置 · 云端连接』绑定你的课题组账号」
- 引导文案仍是**旧绑定语义**（「绑定」「云端连接」字样），与统一登录后的产品语义不符
- 网盘页预期同样中招（同一状态源）

## 根因分析方向（总指挥初判，执行端验证）

M2-3a+ 的 `loginWithCloud` 建立了云端身份（users 行映射 + safeStorage 令牌），但 **M2-3b/M2-3c 数据源的状态判定仍读取 M2-3a 时代的「绑定状态」存储**——该状态只被已退役的「绑定 IPC」置位，统一登录路径**没有联动置位** → 登录了但数据源仍认为「未绑定」。

若证实：**修复方向 = 数据源状态从认证态推导（提供者模式），废除独立存储的绑定状态**——正是 M2-3b/M2-3c 两单反复强调的「外部状态提供者」范式在自己身上的应用。

## 修复要求

1. **状态联动**：云端登录成功（loginWithCloud）后，知识库/网盘数据源必须进入 bound 态；退出登录后回 unbound——以**认证状态为唯一事实源**推导（提供者模式），不维护第二份状态存储
2. **文案统一**：知识库/网盘引导态措辞走集中状态机，语义为「未登录/需连接」；清除「绑定」「云端连接」旧措辞（KnowledgeView 引导文案在 M2-3b 中为硬编码，本次一并接入集中状态机）
3. **回放测试 ≥3**：登录→数据源 bound→列表可拉；登出→unbound；「已登录但数据源 unbound」的不变量断言（防复发）
4. 门禁：689 保持全绿 + 新增 ≥3；零回归

## 真机复验（用户配合）

登录 → 知识库/网盘直接显示**服务器真实数据**（知识库 429 条、网盘真实文件），无引导态。

## 你的任务背景

M8-1 已完成**单条**工具结果的预算与回喂裁剪（32KB 头尾保留），但**多轮累积**仍会撑爆上下文：长会话、多工具轮次、多次大文件读取叠加后，早期内容持续占位。本单实现**会话级上下文预算管理**——在撑爆之前主动裁切早期轮次、保留近端、用 LLM 摘要赎回信息。

M8-1 遗留移交（本单范围内）：
1. 会话级 token 预算 + 早期轮次摘要压缩——可直接复用 M8-1 的 `clipToolResultText` 字节/头尾语义
2. read_file 超长行（压缩 JSON/单行日志）目前只回退返回前段——需提供**按字节窗口的行内读取**能力，让模型能真正续读超长行

技术栈约束同前：主进程与单测零 Electron ABI 依赖；**零新增依赖**（token 估算用启发式，禁止引入 tiktoken 等）。

## 交付物

### 1. token 估算器（`src/main/agent/context/estimate.ts` 纯函数）

- 启发式估算（**保守方向**）：CJK 约 1 token/字、拉丁约 4 chars/token、JSON/代码块修正系数、工具调用结构开销
- 输入：消息数组（system/user/assistant/toolUse/toolResult）；输出：逐条与总量估算
- 误差目标 ±20% 内即可——策略按「宁高勿低」（提前触发好过撑爆）

### 2. 触发线 + 保留近端 + 工具组原子裁切（`src/main/agent/context/prune.ts` 纯函数 + 循环装配）

- 预算：按保守窗口假设配置化（默认按 128k 窗口的 70% 触发、裁到 50%）
- **保留近端**：最近 K 轮（默认 3）与 system 消息永不裁切；最早的用户目标消息保留
- **工具组原子裁切**：一个轮次的 `tool_use` 与对应 `tool_result` 必须同切同留（协议有效性——绝不允许孤儿 tool_result）
- 裁切顺序：最老的「可裁轮次」先动；单轮内先裁工具结果正文（复用 M8-1 头尾语义）再裁整组
- 裁切记录：被裁内容的元信息（轮次/字节/时间）进入会话元数据，UI/日志可查

### 3. LLM 摘要随车（`src/main/agent/context/summarize.ts` + 装配）

- 整组裁切前，把该轮次交给 LLM 生成 ≤200 token 摘要，以一条 system 注记替换原内容（例：「[第 3–5 轮已摘要：…]」）
- 摘要失败/超时 → **降级为纯删除 + 标记**（不阻塞主流程）；摘要请求走 M8-1 的重试装配
- 摘要本身有预算上限；摘要生成期间的用户新消息不阻塞

### 4. read_file 超长行窗口读取（`read-file.ts` 增量）

- 新增 `byteOffset`/`byteLength` 行内窗口参数（针对单行超过 24KB 预算的场景，如压缩 JSON/单行日志）
- 续读提示闭环：超长行截断提示中给出 byteOffset 续读参数；UTF-8 边界安全（同 M8-1 语义）
- 与现有 offset/length（行窗口）参数正交并存

### 5. 可观测性（最小实现）

- 上下文估算总量与裁切事件进日志；设置页调试区（或既有开发者可见处）展示当前会话估算 tokens 与最近一次裁切——**不做大 UI**

### 6. 测试（≥16，全部离线）

- 估算器：中英混排 / 纯中文 / JSON / 代码块 / 空消息 ≥4
- 触发与保留：阈值边界 / 近端保留 / system 永留 / 首条用户目标永留 ≥4
- **原子裁切协议有效性**：tool_use+tool_result 成对同切同留（**构造孤儿场景断言被拒**）≥3
- 摘要：成功替换 / 失败降级 / 预算上限 ≥3
- read_file 窗口：byteOffset 边界 / UTF-8 安全 / 与续读提示闭环 ≥2
- 回归：M8-1 既有用例零回归（自动包含）
